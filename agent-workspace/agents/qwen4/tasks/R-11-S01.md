# 自主子任务：来源—参数可证性矩阵

## 执行步骤
- [x] 重读 R-06 的 CC-01 与 N01–N05/R05/R22 来源记录，确认上一轮到底卡在哪（轴承类型矛盾 + NSK 目录 PDF 正文不可解析）
- [x] 按物理归属分类 8 个关键参数：轴承边界/内部（PR-14/15）、轮毂法兰（PR-16）、轮辋接口（PR-06/07/08）、紧固件（PR-10）、球铰（PR-17）
- [x] 判定每类的可证来源类型，并写明"什么来源才能解锁"（parameterVerdicts[].whatWouldUnlock）
- [x] 排除不可能路径：轴承目录不含 PCD/CB/ET；螺柱目录不含座型与法兰；通用标准不能证明某实车采用某零件
- [x] 确立来源类型分层：制造商官方 HTML（定性）/ 售后件产品页（数值）/ PDF 目录（尺寸表与公差）/ 聚合站（最高二手）/ 论坛（不得当事实）

## 边界
只读 R-06 与 RP-01；不修改任何已验收文件。

## 关键裁定理由
- **先分类再检索**：R-06 已证明"再查一遍轴承网站"不会得到 PCD。本轮把力气放在售后件产品页与制造商技术页两条不同路径上，才拿到 T03 的完整数值。
- **把"标准能证明什么"写清楚**：ISO 6892-1 是拉伸试验方法、ISO 15 是外形尺寸总方案，都不能证明某辆实车的配合。这与总控对 R-08 的返工判定一致。
