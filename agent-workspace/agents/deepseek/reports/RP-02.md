# RP-02 / DeepSeek — SUBMITTED

## 完成了什么（普通人可读）

我把整车拆成六类“接口”来研究：机械力/运动、电能、信息/控制、流体/液压、热交换、接触/环境。每一类都说明了它连接谁、传什么、用什么单位、是单向还是双向、坏了会怎样。然后我用“踩一次刹车、打方向同时过坎、发动机冷却、电车加速/回收”四个场景，把驾驶员或环境的输入一路追到车辆响应；又做了五张变更传播表，说明改轴距、轮距、离地间隙、油车变电车、换悬架拓扑时，哪些零件、装配点、管路、线束、算法和质量属性必须重算。最后我交付了一个可解析的示例接口图（42 个节点、86 条边）和 24 个自动测试，基础图 0 个结构错误，24/24 全部通过。所有具体数值都是示意/推导/假设，不是某辆真实车的实测；CAN 报文、硬点、质量、热标定等未知项都明确标成了 OPEN，没有编造。

## 未完成 / 有争议（不能自行假定已解决）

1. 没有真实车型数据；所有数值为示例/工程推导/显式假设。
2. RP-01 产品树和原 R-02 数据契约尚未提交；节点粒度、`Frame` 类型、`instanceId` 映射、`capability` 枚举、坐标变换仍需总控对齐。
3. 没有 `fidelityLevel`（GEOMETRY/KINEMATIC/DYNAMIC）的正式定义；本报告只提出建议，未擅自填值。
4. 未覆盖结构强度、碰撞、耐久、NVH、EMC、HVAC 制冷剂回路、燃油系统、详细线束/接地。
5. 坐标约定有冲突：现有 Three.js 为 `+Y` 上/`+Z` 前，本报告提案为 `x` 前/`y` 左/`z` 上；未冻结前不得进入生产。
6. 示例图的 `nominal` 值是接口数量级示例，不是同一次工况的自洽解；报告中的算例另行标注为示意。
