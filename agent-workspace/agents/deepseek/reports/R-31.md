# R-31 个人回报：给 5173 主工作台准备了一个只读、可拒绝错误数据的数据入口

## 一句话结果

R-27 的快照已经是一份完整 JSON，但页面直接读它容易把 `INST-*` 当零件号、把演示 GLB 当真实几何、把过期运动当当前。R-31 做了一个独立的只读消费适配器：主工作台通过它拿 13 系统 / 37 总成 / 278 零件的树、稳定的 `PI-*` 选择、详情和状态；数据不对时它会明确拒绝，而不是“尽量显示”。

## 工作台能拿到什么

- **树**：13 个系统 → 37 个总成实例 → 278 个零件实例，支持分页和筛选；265 个没有 R-17 投影的实例不会被藏起来，会标 `R16_CANONICAL_ONLY`。
- **选择**：只认 `PI-*`。保存的选择带 `selectionKey` 和快照 revision，换 revision 后会拒绝恢复，避免把旧选择套到新车上。
- **详情**：零件实例、总成实例、系统、零件定义、总成定义都能查。零件详情会明确给出：无几何、是否有演示轮毂、是否是角色位姿、是否必需但暂缓、是否有数量冲突、关联了哪些冲突。
- **状态**：一眼看到 278 个 `NO_GEOMETRY`、1 个 `DEMO_SUBSTITUTE`、24 项冲突、变型未对齐、严格位姿 STALE、9 帧演示运动。
- **工作台边界**：模型/检查两种模式下，快照都不可编辑、不可保存；保存工程仍归 Composer 的 V2 `ProjectStore`。不会因为接入了整车树就假装快照可以写。

## 三个最容易出错的边界

1. **严格运动默认禁止**：R-23 是 revision 3，快照是 revision 1。调用严格播放会得到 `E_STALE_RUN`；想演示必须显式传 `demoMode:true`、确认徽标、声明源 revision 3，才会返回 `DEMO_ONLY` 的 9 帧。
2. **别名不是身份**：`INST-*` / `ASM-*` 默认会被拒绝；只有显式允许时才映射到规范 `PI-*`，并带“这只是投影别名”的警告。外拉杆的 `INST-SLA-TIEROD-FL` 因为没有实例，会明确返回“必需但暂缓”，不会假装可选或不存在。
3. **哈希不对就拒绝**：创建消费者时必须给快照 SHA-256；缺失或不匹配就直接失败。计数被篡改也会拒绝，不会把半份数据交给页面。

## 给 Composer 的接口

模块在 `src-experiments/vehicle-consumer-v1/consumer.mjs`，浏览器里可以直接：

```js
const consumer = await fetchVehicleConsumer({ snapshotUrl, indexUrl });
const root = consumer.getTreePage({ limit: 50 });
const selection = consumer.selectVehiclePart('PI-20-001-FL');
const detail = consumer.getObjectDetail('PI-20-001-FL');
const status = consumer.getDisplayStatus();
```

完整 API、错误码和接入规则在 `src-experiments/vehicle-consumer-v1/README.md` 与 `docs/research/R-31-vehicle-consumer-contract.md`。R-31 没有改 `workbench-v2/` 的 `index.html/main.js/styles.css/viewport.js`，也没有新端口。
