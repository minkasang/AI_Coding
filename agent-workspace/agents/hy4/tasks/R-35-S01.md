# 03.37.01｜C-01 seed 与生产视窗加载

## 映射规则（已实现）

| 来源 | 目标 | 规则 |
|---|---|---|
| `manifest.instances[].partInstanceId` | `instance.instanceId` / `partKey` / `nodeMatch` | 直接用（9 条） |
| `manifest.instances[].partId` | `semantic` | 映射到 `knuckle / bearingOuter / bearingInner / hub / stud` |
| `manifest.partDefinitions[].displayColor` | `part.color` | 线性 → sRGB hex（`linearToSrgbHex`） |
| GLB 节点 `translation` | `inst.offset` | 直接读 JSON chunk，避免二次加载 |
| `manifest.assets.glb` | `seed.asset` | 同源路径 |

## 为什么必须显式传色

`viewport.js:165` 执行 `mat.color.set(part.color || COLOR[inst.partKey] || '#aec1da')`。
`COLOR` 只有 `hub / bearing / studs` 三个键，C-01 的 5 个 `partId` 全部命中兜底值。
不显式传 `displayColor`，5 个零件会被刷成同一颜色，**可读性实验直接失效**。

转换方向容易错：glTF `baseColorFactor` 是**线性**，`THREE.Color.set('#hex')` 按 **sRGB** 解释。
单测断言「编码后再解码误差 ≤ 1/255」把这条钉住。

## 为什么 offset 必须等于节点 translation

`viewport.js:179` 用 `object.position.set(offset)` **覆盖**节点位移。C-01 把位移烘进 GLB 节点
（如 `PI-30-009-FL-01` = `[0.008, 0, -0.058]`）。传 `[0,0,0]` 会让 5 颗螺柱叠到同一点。

## 冻结的渲染常量（来自生产源码，只读复制）

`exposure 1.18`、`ACESFilmic`、`SRGB`、`PCFSoft`、`fov 38`、视口 `1280×800`、`pixelRatio 1`、
hemi/sun/fill 不动、地面 `-0.096`、网格 `-0.095`、几何法线不动。
