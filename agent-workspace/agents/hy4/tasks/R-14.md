### 技术路线（自主决定）

1. **不换引擎、不换 UI**：R-05 已证明 WebGL 配置本身不低档；问题在轮辋硬边法线、反射内容为空、接地假 AO。R-14 选其中**两类**做可测量对照：
   - **变量 N（法线 / 边缘高光）**：`N0` = 生产 `computeVertexNormals()` 的全硬面法线原样；`N1` = 对同批金属零件几何施加 `toCreasedNormals(geo, 35°)` 的折痕法线。**只改法线**，几何三角数、材质、灯光、相机、曝光全部不变。
   - **变量 G（接地阴影来源）**：`G0` = 复刻 `src/main.js:131-149` 的径向渐变假 AO 贴片、地面不接收真实阴影；`G1` = 去掉假贴片、地面接收真实 PCF 软阴影。**只改接地阴影来源**，其余不变。
2. **2×2 全因子**：`?n=0|1&g=0|1` 四组，固定 1280×800 / 固定相机 / 固定曝光 / 关闭自转，四组完全同源，可反复运行。
3. **A 组用真实生产零件**：实验页直接 `import { createTire } from '/src/tire.js'` 与 `/src/specs.js`，不另造"看起来像"的替身模型；改进只在实验目录内对几何/阴影做变换，生产源码保持只读。
4. **观测工具内置页面**：`renderer.info.render.{calls,triangles}`、`renderer.info.memory`、法线方向量化分布、轮辋 ROI 的高光像素占比与边缘梯度能量、接地接触带的逐列亮度剖面与左右不对称度。所有像素指标在页面内用 `Canvas2D.getImageData()` 读出，避免外部 PNG 解码依赖。
5. **不虚构性能**：headless Chrome 使用 SwiftShader 软件光栅化，仅作为**功能与像素级可复验性**证据；不产出、不声称任何真实 GPU FPS 或显存数字。
6. **不引入外部素材**：不使用 HDRI / 纹理 / CC0 资源，环境光用项目已有的程序化 `RoomEnvironment`，假 AO 用程序化 CanvasTexture。因此无外部许可与文件哈希义务，也不写 C 盘。
7. **隔离边界**：只在 `viewer/experiments/render-quality-v1/` 建文件；**不改** `src/`、`index.html`、`src/workbench-ui.js` 与 5173 生产页面。若结论值得集成，写公共消息给总控 / Composer，不自行改生产。
