## 本轮执行路线（2026-11-15 22:34 冻结）

**基线复核**：`workbench-v2/viewport.js` 当前渲染参数与 R-19 记录逐项一致（`toneMappingExposure=1.18`、hemi `0.9`、sun `2.0`、fill `0.9`、grid `-0.095`、ground `-0.096`、材质强制 `0.70/0.34/1.05`）；Composer 的测距/剖切辅助字段已入库，`git status` 中 `workbench-v2/` 无未提交改动，因此不覆盖任何其它工作位成果。

**关键方法决策**：R-19 是「逐参数手写复刻 V2 场景」，有复刻漂移风险。R-24 改为**直接 import 并实例化生产 `EngineeringViewport`**，再用隔离目录里的 `staging-config.mjs` 在运行时覆写候选参数；好处是 A/B 用的是同一 5173 生产渲染代码，且能真实调用 `load()/sync()` 驱动选中高亮、隔离、爆炸与剖切，而不是模拟这些状态。

**变量顺序（严守一轮一个变量）**：`b` 全基线 → `M`（保留 GLB 自带 PBR 分档，严格单变量）→ `G`（地面高度由 `Box3` 实测 bounds 推导，不写死 `-0.043`）→ `H`（仅 hemi 填光）→ `S`（仅 sun 主光）；另跑 `all` 四变量全开的组合反例，复现 R-19「不能一把合入」的负面信号。

**场景（实跑时由两场景细化为三场景，职责单一）**：`single`（单部件隔离）、`explode`（选中高亮 + 拆解）、`clip`（选中高亮 + 剖切），各跑 iso / side 两视角；原本把爆炸与剖切耦合在一个 `assembly` 场景会让剖切把拆解零件切没、截图不可读，故拆开。

**边界**：不修改 `workbench-v2/viewport.js` 及任何生产页；不新开常驻端口，实验页经 `http://localhost:5173/viewer/experiments/render-staging-v1/index.html` 同源访问；所有候选数值标 `VISUAL_ASSUMPTION`；SwiftShader 只给像素级与 `renderer.info` 数据，不声称真实 GPU FPS/帧时间/显存。
