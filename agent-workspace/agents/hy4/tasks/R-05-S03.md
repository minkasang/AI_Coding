# R-05-S03｜A/B 验证矩阵与性能预算测量方案

## 实际结果（真实完成）

- **基线可复现**：URL `http://127.0.0.1:5173/#mode=tire&tire=0`（`src/main.js:1073-1080` 支持 `mode`、`tire`、`view` hash 参数），窗口固定 1600×1000，Chrome headless 命令与 `--virtual-time-budget` 一并写入报告；`state.spin` 会在 tire 模式自转（`:74`），A/B 前必须关闭「轮辋自转」或固定相位，否则帧不可比。
- **三阶段单变量 A/B**（严格顺序，一次只动一类变量）：
  1. **A 只改摄影棚光照**（几何/材质冻结）：现有 5 灯 → 三档布光对照，记录 exposure / environmentIntensity / 各灯强度。
  2. **B 只改几何**（A 的最优光照冻结）：倒角 0.002→多档、辐条厚度与圆角、轮辋分段数。
  3. **C 只改材质/环境**（A+B 冻结）：常数材质 → 加 roughnessMap/normalMap；`RoomEnvironment` → 真实 HDRI。
  每格固定相机、同分辨率、同一 `#tire` 规格、关闭自转，存 PNG + 参数快照 + FPS 记录；判定用 S05 的 15 项清单 + 像素差分/人工双盲，不以"我觉得更好看"结案。
- **六类性能测量方案**（只给方法 + 本项目基线，**不预设硬指标**）：
  | 指标 | 采集方式 | 本项目静态基线 |
  |---|---|---|
  | 三角数 | `geometry.index.count/3` 遍历 / `renderer.info.render.triangles` | 单胎 44,944–55,844；四胎展台约 200,220 |
  | 对象数 | `scene.traverse` 统计 `isMesh` | 单胎 57–84；四胎展台 255 |
  | draw calls | `renderer.info.render.calls`（含阴影 pass） | 静态下界 63–90 / 279，**未实测** |
  | 加载时间 | `performance.now()` 包围 `GLTFLoader.load` + `LoadingManager.onLoad` | 当前为程序化生成，无 GLB 加载，**不适用** |
  | 显存/纹理内存 | `renderer.info.memory.{geometries,textures}` + 贴图 `宽×高×4×mipmap` 估算；Chrome `performance.memory` 仅作旁证 | 4 张 CanvasTexture（1024²/512²/256²/256²），**未实测** |
  | LOD | 三档距离下切换 `Object3D` 并记录三角数/FPS 曲线 | 当前无 LOD 实现 |
- **FPS 采集方案**：真实 GPU 上用 `requestAnimationFrame` 滑窗统计 + `EXT_disjoint_timer_query_webgl2`（若可用），Chrome DevTools Performance 交叉核对；记录分辨率、DPR、GPU 型号与是否为 SwiftShader。
- **两个性能档位建议**（明确 `PLAN_ONLY`）：高画质档保留高密度辐条 + 全分辨率贴图 + 软阴影；轻量档用 InstancedMesh 合并螺栓/散热孔、降 Lathe 分段、贴图降至 512²、关闭次要投影。两者均**建议待测试**，不是已实测方案。
- **不做什么**：未改 `src/`、未装依赖、未实测 FPS、未把软件渲染帧的性能当结论；未把 `RP-04` 的 `60 FPS / DrawCall ≤150` 目标抄成硬指标（那也是未实测目标，见 RP-05 v1.3 审计）。
