## 测量口径（为什么这样测）

1. **不用「选中前后逐像素差分」测零件颜色**：选中会触发 `viewport.focus()` 移动相机，
   两帧不是同一投影。改用页面自带「隔离选中零件」，逐件单独渲染再按色度分类取像素。
2. **必须裁到模型区**：不裁会把顶部工具条、底部状态条、右下 WebGL 角标的文字算成零件
   （转向节隔离失败时曾测出 4265 个「零件像素」，实际全是 UI）。
3. **隔离视图要判空**：零件像素 <3000 视为隔离为空，不给颜色结论，避免 UI 残留冒充零件。
4. **整体可见性用高亮差分**：树点选后在**未高亮**的原图上按差分遮罩取轮廓，
   得到默认机位下真实的共视面积；轴承为 0 直接说明「整体视图看不见轴承」。
5. **颜色比较用线性色比**：白光对漫反射只做等比缩放，`r/g`、`b/g` 对光强不敏感，
   可与 manifest 的线性 `displayColor` 直接比；绝对亮度不可跨渲染器比较。
6. **相机必须收敛后再拍**：`stableShot()` 连拍到两帧逐像素一致才落盘，
   否则会把相机漂移当成剖切效果（首版就因此差出 2.5 万像素）。

## 限制

- 后端是 **headless Chrome + SwiftShader 软件光栅化**，只做像素级可复验取证，
  不代表真实 GPU 的帧率、帧时间或显存表现。
- C-01 素材为 `DEMO_ASSUMPTION`（`sourceGrade`），几何与颜色**不构成 OEM 尺寸或材料认证**。
- 本轮只验「正常路径」。R-36 的绑定校验缺口（捕获 `E_SNAPSHOT_MISMATCH` 后仍以 9 节点继续渲染）
  属返工范围，不计入视觉结论。
- 被测生产文件指纹：`main.js b8d61ec8`、`viewport.js 469e96b5`、`index.html 9c3686e7`、
  `c01-viewport-mode.mjs 37b21e48`（2026-11-22 12:19 版本）。生产文件若再变，本证据需重跑。
