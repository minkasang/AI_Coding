# R-14 · 金属机械质感 A/B 实验（隔离样板）

> 归属：HY4 / `R-14`（03.16）· 正式报告见 `docs/research/R-14-render-prototype.md`
> **本目录是隔离实验，不是产品页面。** 统一用户入口仍是 `http://localhost:5173` 五视图「小车工程工坊」；
> 本实验独立跑在 `5181`，不改 `src/`、`index.html`、`src/workbench-ui.js`，不改 5173 的任何一行。

## 1. 这个实验回答什么

R-05 的结论是：画质问题不在「WebGL 不行」，而在轮辋**硬边法线**、程序化白盒反射、以及**假 AO 贴片接地**。
R-14 从中挑两类，做能反复运行、能出数字的「现状 vs 改进」对照，而不是再换一套 UI 配色。

| 变量 | 0（现状基线） | 1（单变量改进） | 保持不变 |
|---|---|---|---|
| **N** 法线 / 边缘高光 | 生产 `computeVertexNormals()` 的非索引三角汤，全硬面法线 | 对同一批金属零件几何施加 `toCreasedNormals(35°)` 折痕法线 | 几何三角数、材质、灯光、相机、曝光、环境、自转 |
| **G** 接地阴影来源 | 复刻 `src/main.js:131-149` 的径向渐变假 AO 贴片，地面不接收真实阴影 | 移除贴片，地面接收真实 PCF 软阴影 | 同上 |

`?n=0|1&g=0|1` 构成 **2×2 全因子**，四组共用同一份生产源码与同一套固定参数，可以看主效应，也可以看交互。

## 2. 复现

前置：项目根目录已 `npm install`（需要本地 `three@0.170.0`）；Node ≥ 18；本机 Chrome。

```bash
cd viewer/experiments/render-quality-v1

# 方式 A：一键（自动启停 5181 服务、跑 4 组、出指标与截图、退出）
node run-ab.mjs

# 方式 B：手动开服务后用浏览器看任意一组
node server.mjs
#   http://127.0.0.1:5181/?n=0&g=0
#   http://127.0.0.1:5181/?n=1&g=1

# 校验四组结果与单变量约束
node verify.mjs
```

`run-ab.mjs` 可用 `CHROME_PATH` 指定 Chrome，`R14_PORT` 改端口。它把 Chrome 的 user-data-dir 与磁盘缓存显式放在
`F:/tmp/r14-chrome/`，**不向 C 盘写用户配置，也不下载任何素材**。

## 4. 指标口径（`metrics.js` 顶部有同一份说明）

- **luma** = `0.2126R + 0.7152G + 0.0722B`，直接作用于 8-bit 显示编码值，**不做 sRGB→linear 反变换**。
  只用于四组间相对比较，不是物理亮度。
- **轮辋 ROI**：以轮心投影为中心、边长 `2 × 轮辋半径投影 × 0.9` 的正方形；四组完全一致。
  - `highlightRatio`：ROI 内 luma ≥ 205 的像素比例（金属白色高光的粗略代理）。
  - `edgeGradient`：ROI 内 `|L(x+1,y)-L| + |L(x,y+1)-L|` 的均值，反映局部明暗跃变。
- **接地接触带**：以地面接触点投影为中心、其下方 22 px 高的横条，横向分 32 列求列平均亮度。
  - `asymmetry` = 左 1/3 均值 − 右 1/3 均值。假 AO 是旋转对称的径向渐变，真实阴影随光源偏斜，
    该值能把「有没有方向信息」变成数字。
  - `centerEdgeRatio` = 中间 1/3 均值 ÷ 两侧均值，< 1 表示接触中心更暗（有接触遮蔽感）。
- **法线分布**：方向量化到 0.02 粒度后的唯一方向数与香农熵。用于证明 N 变量**只改了法线**，
  不是几何或材质偷偷变了；不预设方向数一定变大或变小。
- **绘制统计**：`renderer.info.render.{calls, triangles}`、`renderer.info.memory.{geometries, textures}`。
  这是**绘制次数/三角数，不是 FPS**。

## 4.1 实跑结果摘要（2026-11-15 01:50，完整表见 `results/ab-summary.md`）

| case | N | G | calls | triangles | 唯一法线 | 高光占比 | 边缘梯度 | 接地不对称 | 中心/两侧 |
|---|---|---|---|---|---|---|---|---|---|
| `n0g0` | 0 | 0 | 66 | 56,024 | 5,010 | 0.037026 | 13.1087 | 5.609 | 0.6168 |
| `n1g0` | 1 | 0 | 66 | 56,024 | 7,128 | 0.034320 | 11.8616 | 5.609 | 0.6168 |
| `n0g1` | 0 | 1 | 65 | 56,022 | 5,010 | 0.037026 | 13.1525 | 0.418 | 0.7156 |
| `n1g1` | 1 | 1 | 65 | 56,022 | 7,128 | 0.034320 | 11.8609 | 0.418 | 0.7156 |

- **N 单变量成立**：法线方向数 +42.3%，三角数与 draw call 一个数都没变。
- **G 反直觉**：换真实阴影后接触带最暗值 73.92 → 84.10、中心/两侧 0.6168 → 0.7156，
  轮胎**更飘**。原因是本实验刻意保持的高环境填光把主阴影填平了（详见报告 §5.2）。
  → 替换假 AO 必须与环境填光**一起调**，不能只做一个开关。
- `node verify.mjs`：`FINAL_CHECKS_FAIL=0 / RESULT: PASS`。

## 5. 已知限制（不要越过这些边界下结论）

1. **软件光栅化**：headless Chrome 使用 `--use-angle=swiftshader`，像素结果可复验，
   但它**不是真实显卡**。本实验不产出、不声称任何硬件 FPS、帧时间或显存数字；真实 GPU 性能仍为 `OPEN`。
2. **`preserveDrawingBuffer: true`**：为让 `Canvas2D.getImageData()` 能读到 WebGL 画布而开启，
   有额外拷贝开销，不应移植到生产页面当默认配置。
3. **G0/G1 是隔离后的两个极端**：生产现状同时存在贴片、软阴影与较高环境填光。
   本实验刻意把「只有假贴片」和「只有真实阴影」分开，以便测出各自贡献；
   **不是**对 5173 画面的逐像素复刻。贴片纹理的生成代码本身是从 `src/main.js` 原样复刻的。
4. **环境填光未调**：`HemisphereLight 0.58` + `environmentIntensity 1.0` 与生产一致，
   因此 G1 的真实阴影仍会被填得偏淡。这正是 R-05 指出的「主阴影被环境光填平」，
   本轮**不额外降低环境光**，否则会引入第三个变量。
5. **`toCreasedNormals` 的顶点哈希**：three r170 内部按 `~~(v * 100)` 量化顶点位置（约 1 cm），
   在毫米级倒角上可能把邻近顶点误判为同一点。这是工具本身的近似，任何视觉副作用都应在真实 GPU 上复核。
6. **相机前倾未复刻**：生产展台给轮胎加了 `rotation.x = -0.17` 的前倾；为了让「轮胎接地」有明确定义，
   本实验让轮胎保持竖立，只保留 `rotation.y = -0.40` 的斜角。
7. **无外部素材**：未使用 HDRI / 纹理 / CC0 资源，环境光为程序化 `RoomEnvironment`，
   假 AO 为程序化 `CanvasTexture`。因此没有外部许可、出处与文件哈希需要登记。
8. **未验证的部分**：没有真实制动盘材料参数、没有厂家来源的材质数据；
   轮辋材质沿用 `src/specs.js` 的**假设值**，不冒充真实工程参数。
