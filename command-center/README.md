## 页面功能

- **指挥总览**：7 个模型、全部任务数量、等待领取/进行中/待审/验收数量和步骤完成率。
- **模型专属看板**：点击模型查看职责、当前优先事项、专属任务列表和真实步骤比例。
- **任务详情**：点击任务查看当前步骤、步骤树、怎样实现、一个相关技术知识点、最近汇报、详细任务书路径。
- **总任务池**：状态筛选、模型/任务搜索，支持层层查看。
- **自动同步**：网页每 8 秒重新读取 `agent-workspace/agents/*/tasks/*.md`，文件修改会更新；浏览器标签重新进入前台也会刷新。
- **自适应布局**：桌面侧栏、窄屏和手机底部导航；具备柔和动效及减少动态效果设置支持。

## 重要：任务卡单一数据源

- 正式状态只能在各模型 `agent-workspace/agents/<model>/tasks/<task>.md` 修改。
- 修改 `status:`，以及 `## 执行步骤` 中的 `- [ ]` / `- [x]`；网页会自动刷新。
- `summary` 是一句话概述，`method` 是如何做，`learning` 是通俗技术知识，`lastNote` 是最近一项真实进展。
- 步骤比例按复选框计算；对有子步骤的任务只计入叶子步骤，**进度不是随机百分比**。
- **V1.1 交互**：网页的任务派发区可直接复制完整任务提示词，用户粘贴给对应 AI；AI 完成后可在网页粘贴回报，接口写入其专属 `reports/<taskId>.md`，并将原任务 Markdown 的 `status` 设为 `submitted`。其他任务状态和步骤仍由模型/总控维护。
- **回报不是验收**：收到外部 AI 文字回报后仅表示待审；需要 GPT-6 复查实际文件、测试命令和资料证据后，才能人工改为 `approved`。网页提供“复制回报给 GPT-6 审核”。
- **并发保护**：保存回报时检查任务卡更新时间；若有其他 AI 已修改，界面要求先刷新，不能强制覆盖。重复回报自动保留之前的回报副本至 `reports/history/`。
- 文件更新时间只是磁盘写入时间，不等于模型当前在线/执行中。状态值是模型主动填写，不是后台进程监控。
- 看板只对**回报接收**开放有限的本地写入接口，其他项目源码及任务步骤不能通过网页随意修改；服务绑定 `127.0.0.1`，不对公网提供访问，且不自动联系外部 AI。
- 任务增加、移交、新模型加入只需要按 `agent-workspace/MASTER_TASKS.md` 的规范修改文件。

## V1.2：执行 AI 自主规划与子任务

总控 GPT-6 负责高质量目标提示词、约束和验收；执行模型负责研究、制定工作计划、创建子任务及执行。正式协议：`docs/command/PROMPT_AND_DELEGATION_STANDARD.md`，并已提升为根目录 `AGENTS.md` 第 0 节的硬性要求。

原先尚未开始的任务已清理预填复选框，其探索方向保存在原任务卡 `## 可选探索方向` 下；在领取前，网页显示 **待规划**，不把空步骤强行算为 0% 工程进度。

模型如创建 `agent-workspace/agents/<modelId>/tasks/RP-01-S01.md` 并声明 `parentId: RP-01`、唯一 `id`、`displayCode: 02.02.01` 等基本字段，网页会自动读取并在父任务详情中展示子任务，父任务按子任务已定义的真实执行步骤计算进度。任务数会随模型分解而动态增长；未启动的模型不需要预先创建大量空步骤。完整 Markdown 模板见上述协议。

主界面右上角的完成比例**不是整车项目完成率**：目前展示有记录可跟踪执行步骤的父任务数；工程是否达到目标仍需独立验收。没有模型后台连接时，页面仍由用户复制提示词、模型编辑文件或用户粘贴回报来同步。
## V1.3：AI 直接写文件 → 看板自动发现 → GPT-6 按需审核

**默认流程已改为共享文件协作，不要求用户从外部 AI 复制回报：** 在有真实项目目录访问权限的 AI Coding 工具里，用户启动一次主模型任务；模型自己创建/管理子任务，实际能调用子代理时内部调用，否则在主会话执行。进度写 `agent-workspace/agents/<modelId>/tasks/*.md`，主报告写 `reports/<taskId>.md`；工程文档和证据按任务书存放。

看板现在自动扫描 `docs/planning/reports/`、`docs/planning/evidence/`、`docs/research/` 中以任务 ID 开头的 Markdown/JSON/CSV/TXT/SVG 文件，并在任务详情里展示“已发现的成果文件”和相对路径。个人报告也照常读取，所有文件都不需要用户二次转发。

看板的“粘贴 AI 回报”仅是**纯网页聊天模型无本地文件权限时的备用入口**。模型已提交结果后，用户直接对 GPT-6 说“检查 CARLAB 已提交任务”即可，我会通过连接的本机项目检查文件并审核；**看板不主动唤醒 GPT-6 或其他模型**。子任务不需要用户逐条复制提示词。

完整的分工、能力限制和文件约定见 `docs/command/FILE_HANDOFF_PROTOCOL.md`；`AGENTS.md` 第 0.1 节是所有模型最高优先级的入口。任务状态和报告不同源：状态仍只在任务卡里，报告是交付证据。存盘成功不等于通过验收。

## 模型下一轮任务（2026-11-14）

总览和任务派发页新增“各模型下一步”。页面按**父任务**状态选择每个模型的当前主工作，优先显示进行中、待返工、可领取或待审核的任务，已验收的历史工作不再冒充新的工作。若只有暂缓任务则显示“尚未解锁”，完全没有可续工作则显示“待总控安排”。点击卡片可查看对应任务和验收要求。

这个栏目只读取现有 Markdown，与审批状态同源，不能直接启动外部 AI，也不代表模型此刻在线。总控每次审核都应检查续派是否覆盖所有可并行模型，依赖与安全门禁仍有效。
