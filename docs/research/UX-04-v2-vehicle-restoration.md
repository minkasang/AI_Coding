# UX-04｜V2 整车、工程项目入口与跟随相机恢复验收

> 2026-11-15 · GPT-6 · 用户明确反馈 V2 仅剩左前轮，整车实验缺失，工作空间/汽车项目不可点击。**本次针对具体问题修复，不将它描述成完整工程汽车已建成。**

## 用户指出的缺陷与现状

原 V2 仅显示三类演示 CAD 零件（法兰、轴承包络、螺柱集合），以“工程工作台”称呼却没有默认整车入口；“工作空间 / 汽车项目”是纯文字。原有的整车/轮胎/悬架/传动演示并没有整合到 V2。用户指出这些问题完全成立。

## 实际完成

1. **整车实验默认显示**：`workbench-v2/index.html` 现在默认进入 `整车实验`。通过同源 iframe 调用仍在维护的旧 `../index.html#mode=vehicle`，而不是重做另一辆低精度车。原有驾驶控制、冲减速带、跌落/轮胎/悬架/传动场景仍可用。V2 的整车实验内部以小型局部子导航切换，隐藏重复的旧顶层导航；保留旧页面独立链接。
2. **轮端工程仍可编辑**：顶部 `零件装配` 返回 V2 单一 Three.js 工程视窗和 ProjectStore，不丢原有工程编辑、零件选择、JSON 出入和撤销/重做。
3. **真实可点击的项目入口**：顶部 `工程项目`、面包屑 `工作空间`、`汽车项目`、工程名称都进入项目列表；卡片可进入整车实验、轮端编辑，或创建空白工程。保存数据通过当前浏览器 localStorage / JSON 导入导出；**这还不是跨设备多项目后台数据库**。
4. **页面语义区分**：整车实验在面包屑显示“整车实验 · 简化演示车”，不再显示误导性的“轮端装配工程”名称；工程装配显示自己的名称。整车视图隐藏仅用于装配工程的“导出/撤销”工具栏，避免作用对象混淆。
5. **旧版航向跟随相机错误修复**：`src/main.js` 原先只把车身 `chassisPosition` 的平移增量施加给镜头和 OrbitControls，转弯时镜头不会跟着航向转。新的 `src/camera/followVehicle.js` 根据车体四元数提取绕 Y 轴航向，用最短角度把当前 Orbit 偏移旋转，同时保持手动相机视角。即使追随关闭也更新参考，避免重新打开时突然跳转。未改变 Cannon-es 真实物理精度。
6. **运行效率**：V2 零件 GLB 视窗在整车/项目页非活动期间暂停渲染；原有简化整车实验维持原物理求解逻辑与独立资源边界。两个系统目前仍不共享真正的整车工程实例/机械约束图，嵌入属于**阶段性恢复功能**，不是长期架构。

## 当前仍然缺少，不能误称完成

- 高精度完整车辆的 CAD、可拆全车零件/螺栓、真实装配基准、真实多体悬架/转向机构运动约束、碰撞干涉/有限元：**尚未实现**。
- 现有四轮车是原来的低保真驾驶演示，与轮端 CAD 仍是两个独立模型。尚未接通“选中整车上的一个真实转向节 → 直接进入其工程装配/动力学约束”的统一映射。
- 项目页是真入口，现阶段只管理浏览器内一个活跃工程与示例/空白入口，未实现多工程数据库、版本协作和云端同步。
- 旧物理引擎依然是 Cannon-es RaycastVehicle，不能拿摄像机修复结果证明车辆底盘力学已正确建模。
