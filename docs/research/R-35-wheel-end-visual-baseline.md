## 1. 任务与预设

任务书要求：把 R-30 在旧轮端上验证过的 PBR 单变量对照，用到 C-01 新 GLB 上，
判断轴承内外圈、轮毂、转向节与五颗螺柱能否在整体与局部观察中清晰区分。

这里有一个**隐含预设**：新资产也存在「GLB 原生 PBR 分档」，可以通过恢复分档获得零件区分度。

开工资格检查时发现该预设不成立，本轮据此调整了工作重心：

- 仍然完成要求的三组机位 A/B 与可读性判定；
- 但把主要结论从「M 策略是否有效」转为「**该资产的零件区分到底靠什么**」。

## 2. 开工即证伪的资产事实

直接读 `wheel-end.glb` 的 JSON chunk（不加载 geometry）：

| 材质 | baseColorFactor（线性） | metalness | roughness |
|---|---|---|---|
| cast steel assumption | 0.24 / 0.30 / 0.36 | **0.72** | **0.34** |
| bearing steel assumption | 0.42 / 0.47 / 0.53 | **0.72** | **0.34** |
| bearing steel assumption.001 | 0.65 / 0.69 / 0.74 | **0.72** | **0.34** |
| forged steel assumption | 0.52 / 0.56 / 0.62 | **0.72** | **0.34** |
| fastener steel assumption | 0.28 / 0.32 / 0.38 | **0.72** | **0.34** |

- 原生 PBR **只有一档**：`0.72 / 0.34`。
- 生产覆盖值是 `0.70 / 0.34 / 1.05`（`workbench-v2/viewport.js:166-167`）。
- 二者只差 **metalness 0.02**，roughness **完全相同**。

对比 R-24 / R-30 使用的旧轮端：hub `0.85/0.25`、bearing `0.95/0.12`、studs `0.80/0.50`，**三档**。
旧资产有分档可恢复，新资产**没有**。

所以「R-30 的 M 策略能否迁移」的答案是：**能迁移代码，但没有可迁移的收益**。

## 3. 为什么必须自己重建 seed，而不是直接 load GLB

生产视窗的两处行为决定了不能"把 GLB 丢进去就行"：

1. **颜色会被覆盖。** `viewport.js:165`：
   ```js
   mat.color.set(part.color || COLOR[inst.partKey] || '#aec1da');
   ```
   `COLOR` 只有 `hub / bearing / studs` 三个键，C-01 的 5 个 `partId` 全部命中兜底 `#aec1da`。
   不显式传色 → 5 个零件同色 → 可读性实验失效。

2. **位移会被覆盖。** `viewport.js:179`：
   ```js
   object.position.set(n(offset[0]), n(offset[1]), n(offset[2]));
   ```
   C-01 把每个实例的位移烘进 GLB 节点（例如 `PI-30-009-FL-01` = `[0.008, 0, -0.058]`）。
   不传 offset → 5 颗螺柱叠到同一点。

因此 `c01-seed.mjs` 做两件事：`displayColor` 线性→sRGB 编码后写入 `part.color`；
从 GLB 节点读 `translation` 写入 `inst.offset`。两条都有单测断言。

颜色编码方向容易搞错：glTF 的 `baseColorFactor` 是**线性**值，而 `THREE.Color.set('#hex')`
按 **sRGB** 解释。直接 `Math.round(v*255)` 会得到明显偏暗的颜色。单测以「编码后再解码，误差 ≤ 1/255」
把这件事钉住。

## 4. 可读性怎么测：分割图 + 同帧外观图

### 4.1 为什么不用逐零件隔离

隔离渲染隐藏其他零件，同时**去掉相互遮挡与相互投影**。测出的分离度是上界，
回答不了「这两个零件放在一起会不会糊」。而"糊不糊"恰恰是任务要问的。

### 4.2 实际做法

1. 正常渲染一帧外观图（生产材质、生产光照）。
2. 把每个实例临时替换成唯一纯色 `MeshBasicMaterial`，关闭色调映射，渲染一帧 → **零件分割图**。
   环境网格（地面、网格线，无 `userData.instanceId`）在本次渲染中隐藏。
3. 用分割图在外观图上取每个零件的像素集合，计算其表观亮度均值与标准差。
4. 同语义的多个实例（5 颗螺柱）按像素加权聚合。

分割图与外观图同机位、同投影、同遮挡，所以测的是真实共视条件。

一个实现细节：`renderer.info` 每次 `render()` 会重置，所以渲染统计必须在 `shoot()` 后**立刻**读，
否则会被分割图那一帧的计数污染（分割图只有零件、没有地面）。

### 4.3 判定阈值与其局限

`DISTINCT ≥ 12`、`MARGINAL ≥ 6`、`BLEND < 6`（0–255 亮度单位）。

这是**工程经验阈值**，用于本资产内部的相对排序，不是感知标准：没有做 CIEDE2000、
没有标定显示器、没有做人因实验。报告里所有 DISTINCT/MARGINAL 都应这样理解。

## 5. 结果

### 5.1 两臂差异是噪声级

| 机位 | 对比度 | 均值亮度 | 边缘梯度 |
|---|---|---|---|
| full | 31.006 → 31.720（+0.714） | 208.90 → 208.15（−0.75） | 1.6313 → 1.6596 |
| bearingIsolated | 25.288 → 25.851（+0.563） | 209.70 → 208.94（−0.75） | 0.8538 → 0.8758 |
| hubStack | 25.174 → 25.714（+0.540） | 195.98 → 195.05（−0.93） | 1.0226 → 1.0439 |

逐零件更清楚：**每个零件的 B 臂都比 A 臂暗约 1.2 亮度单位**，方向一致、幅度均匀：

| 零件 | A | B | Δ |
|---|---|---|---|
| 转向节 | 170.30 | 168.37 | −1.94 |
| 轮毂 | 196.46 | 195.56 | −0.90 |
| 螺柱 01 | 186.90 | 185.72 | −1.18 |
| 螺柱 03 | 185.06 | 183.80 | −1.26 |
| 轴承外圈 | 192.28 | 191.07 | −1.21 |
| 轴承内圈 | 212.28 | 211.60 | −0.69 |

这是 metalness 0.70→0.72 的物理结果：漫反射略降、镜面略升，整体略暗、对比略高。
**没有任何一个零件出现方向相反的异常**，也没有任何零件的相对排序被改变。

对照 R-24 的 M 单变量：对比度 **+12.254**、边缘梯度 **+1.7697**。本轮最大 +0.714，是其 1/17。

### 5.2 整体视图：轴承根本看不见

`full` 机位（全部 9 个实例）逐零件像素：

| 零件 | 表观亮度 | 像素占比 |
|---|---|---|
| 转向节 | 170.30 | 30.2% |
| 轮毂 | 196.46 | 58.8% |
| 螺柱（5 颗合计） | 186.45 | 9.8% |
| 轴承外圈 | — | **0** |
| 轴承内圈 | — | **0** |

轴承内外圈在整体视图中被转向节与轮毂**完全包住**，一个像素都看不到。

这是一个必须写进结论的事实：任何"从整体视图判断内外圈是否可区分"的验收方式都是无效的，
它测不到东西。必须用隔离或剖切机位。

可见零件之间的分离度：

| 对 | ΔL | 判定 |
|---|---|---|
| 转向节 / 轮毂 | 26.2 | DISTINCT |
| 转向节 / 螺柱 | 15.6 | DISTINCT |
| 轮毂 / 螺柱 | 10.6 | MARGINAL |

`轮毂 / 螺柱` 落到 MARGINAL，但原因不是材质：螺柱在整体构图里只占 9.8% 像素，
单颗约 1,700–2,800 px，主要靠凸起轮廓而非亮度差被识别。这是**取景与尺度**问题。

### 5.3 局部视图：内外圈可区分，但靠的是 baseColor

`bearingIsolated`（只显示轴承外圈 + 内圈）：

| 零件 | 表观亮度 | 像素 | 近白比 |
|---|---|---|---|
| 轴承外圈 | 192.28 | 253,076 | — |
| 轴承内圈 | 212.28 | 163,905 | — |

**ΔL 20.0 → DISTINCT**。但这个 20 的来源是 `baseColorFactor` 差异
（内圈 0.65 vs 外圈 0.42，线性），不是 PBR 分档——两者 PBR 完全相同。

同时记录一个偏亮问题：该机位整体近白比 **0.26**、内圈均值 **212**，两者都落在高亮区，
色相几乎相同（都是中性灰蓝）。可区分主要依靠环形几何边缘与明暗台阶。

`hubStack`（只显示轮毂 + 5 螺柱）：

| 零件 | 表观亮度 |
|---|---|
| 轮毂 | 184.68 |
| 螺柱（5 颗） | 169.43 |

**ΔL 15.3 → DISTINCT**。但五颗螺柱彼此差 **18.3**（160.7 ~ 179.0）：
同一批零件因朝向不同明暗差别很大，说明"螺柱"不能当作均匀色块来设计对比。

### 5.4 结构与成本未变

| 项 | 结果 |
|---|---|
| 两臂世界矩阵 | 三机位全部逐值相同 |
| draw call | 11 / 4 / 8，两臂相同 |
| 三角形 | 38,488 / 27,178 / 8,012，两臂相同 |
| 几何 / 纹理 | 两臂相同，纹理 0 |

材质改动只动标量，不增几何与 draw call，符合预期。

## 6. 结论

1. **R-30 的 M 策略在 C-01 上是 no-op。** 该资产 GLB 只有一档原生 PBR，
   「恢复分档」没有对象可恢复。不要为它接入 feature flag。
2. **可读性现状可接受。** 三组关键对在合适机位下都达到 DISTINCT；
   唯一 MARGINAL 是整体视图的"轮毂 vs 螺柱"，成因是尺度而非材质。
3. **区分度全部来自 `baseColorFactor` 与几何边缘。** 五个材质色集中在中性灰蓝带内，
   色相几乎相同，靠亮度分层；这在隔离视图下够用，但没有色彩冗余。
4. **错误的验收方式必须排除。** 整体视图看不到轴承，不能用来判断内外圈。

## 7. 建议

1. **不建议**为 C-01 接入 M feature flag（收益 1/17，成本是一个新开关面）。
2. 若要进一步提升可读性，杠杆在**资产侧**（C-01 / Codex）：
   - 给螺柱更暗的 `baseColor`，或加大头径，提升整体视图下的辨识；
   - 给内外圈加入色相分离（当前全靠亮度）；
   - 整体降低 `baseColor` 亮度以缓解轴承隔离视图的近白问题（0.26）。
3. 页面接入由 Composer 负责；接入时建议**直接用隔离/剖切机位做轴承验收**，
   不要用整体视图。
4. 换 GLB 后必须重跑 `verify.mjs` 第 1 组（原生档位断言），因为本资产"单档"的结论是资产特定的。

## 8. 边界

1. **无真实 GPU 数据**：headless Chrome + SwiftShader，只给像素级截图与 `renderer.info`，不谈 FPS / 帧时间 / 显存。
2. **材质为 `DEMO_ASSUMPTION`**：五条"assumption"是 C-01 参数化假设，不是厂商材料参数或 OEM 认证。
3. **未接主工作台**：仅在隔离页使用生产 `EngineeringViewport` 类验证。
4. **阈值未做感知标定**：DISTINCT / MARGINAL / BLEND 是内部相对排序，不是行业标准。
5. **单资产结论**：换资产后原生档位与色板都可能不同。
6. **分割图边缘损失**：抗锯齿边缘被判为背景，零件像素数略小于真实投影；两臂一致，不影响对比。
7. **未覆盖**：装配位置正确性（由 C-01 自身验证）、运动学、真实 GPU 表现、多视角遍历（只取三个固定机位）。
