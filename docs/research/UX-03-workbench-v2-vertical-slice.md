# UX-03｜CARLAB V2 工程工作台纵切实证（GPT-6）

**2026-11-15｜隔离工程原型已实现，生产集成未批准。**

## 发生了什么

用户明确要求项目从一个有很多 Bug 的整车展示网页，转成可逐步搭车、理解零件身份、连接运动与仿真的工程工作台，且强调不能“光说得好”。因此本轮总控没有对正在被其它代理编辑的旧应用继续堆 CSS，也没有改造尚未冻结的机械和接口协议，而是在 `workbench-v2/` 实际实现一个可运行的“数据 → 交互 → 3D → 保存/导出/导入”最小工程闭环。

**实际地址**：`http://localhost:5173/workbench-v2/index.html`（当前简单 Node 静态服务器不支持子目录短 URL）。

## 本轮关键质量门

| 用户动作 / 工程问题 | 真实实现 | 证据 |
|---|---|---|

| 不破坏其它模型 | 全部代码新增在 `workbench-v2/`，无既有生产模块直接变更 | Git staged path 逐项核查 |

## 已知问题／不能夸大的能力

- **没有真实装配约束和物理求解**：该版仅具备可追踪工程对象模型、真正 WebGL 点击选择与视觉拆解，不存在机构仿真计算或真实越野城市物理。
- **目前只可添加三类示例资产**：其中螺柱还是聚合节点，缺逐螺栓工程实例；并非 500 件完整汽车。
- **工程 schema 为独立 DEMO 约定**：跨模型 PartSpec/BOM/Joint/Frame 尚未完成 RP-07 决策；不能把演示 JSON 当成正式生产共享契约。
- **模型几何仍较简单**：页面更清晰不等于车轮/轴承建模精度达到用户的最终期待。真正的机械质感需要 CAD 几何细节与可验证的材质工作流。
- **测试覆盖真实浏览器点击，不是工程安全验证**：还没有通过 RTX 5060 实际 GPU FPS、移动设备、内存泄漏和长时运行的对照测试。
- **旧页面相机跟随问题尚未改**：本版视窗有独立 OrbitControls，不能拿它的通过冒充旧 RaycastVehicle 航向相机已修复。

## 结论和下一步

本次纵切达到“可以给其它 AI 学习和扩展的真实、测试过的最小平台骨架”目标。推荐保留旧 5173 四大展示模式作为回归；下一轮由总控结合 RP-07 从该隔离样板稳定接口入手，研究真实轮端机械约束，再逐步替换旧主页。任何合并需重新进行 Chrome 基准截图与错误/状态回归。
