# CARLAB｜共享文件协作与内部子代理闭环

> 生效：2026-11-14。此协议定义 **默认的本机 AI Coding 协作方式**。手动复制聊天结果仅用于模型不能直接读写项目文件的情况。
> 用户负责启动每个主 AI 的第一段会话；主 AI 之后自行管理其职责范围内的子任务。总控 GPT-6 在用户再次调用时读取同一文件系统，执行审核与下一轮派工。

## 1. 实际运行边界

**可实现**：不同 AI 工具只要真正挂载同一 Windows 项目目录，就可以独立读取任务目标、在自己的任务目录新建子任务、执行命令、写入报告/代码/证据；本地网页以文件为数据源自动汇总。GPT-6 有项目文件访问权限时可以直接核查，不用用户复制报告。

**不能自动保证**：所有聊天网页都有文件权限；所有模型均能在后台持续运行；所有工具均有“创建子代理/新会话”API；GPT-6 在未被用户调用时会主动观察任务；任务状态 `in_progress` 表示模型一定在线。若工具实际不支持子代理，主 AI 可以在同一会话内按其自主规划顺序处理子任务，不能强行调用不存在的能力或把任务再抛回用户。

## 2. 标准交接闭环

```text
GPT-6 创建主任务：tasks/<taskId>.md + docs/tasks/<brief>.md
      ↓
用户仅启动各主 AI 的会话（在有真实文件访问权的 AI Coding 工具中）
      ↓
主 AI 自己读取 AGENTS.md/PROFILE.md/任务书
      ↓
主 AI 根据实际需要拆子任务（同模型 tasks/*-SXX.md，parentId 关联）
      ↓
能调用子代理的工具：内部委派 + 回收成果；不能调用：主 AI 自行顺序执行
      ↓
每项执行：更新任务卡的状态、真实复选框和一句话 lastNote
      ↓
各自输出研究/源码/测试/证据；提交到任务说明指定目录
      ↓
主 AI 汇总成果并写自己 reports/<parentId>.md，主任务 status: submitted
      ↓
网页自动展示“待审核”与成果目录；用户只需对 GPT-6 说“检查任务 02.xx”
      ↓
GPT-6 直接读本地任务、报告、资产并重跑必要测试
      ├── APPROVED → 记录审查、改任务卡为 approved，开放下游任务
      ├── NEEDS_WORK → 记录缺口，退回主 AI 目录
      └── BLOCKED → 标明缺少的证据或权限/依赖
```

## 3. 每个模型必须遵守的文件契约

统一状态源（唯一）：`agent-workspace/agents/<modelId>/tasks/<taskId>.md`。

- `status`、`lastNote`、`## 执行步骤` 真实反映进度，子任务用 `parentId` 关联。
- 主任务可以自行创建、调整、合并或归档其**所属模型**的子任务，任务 ID 全局唯一且历史成果不得被覆盖或伪造。
- 各模型自行提交回报：`agent-workspace/agents/<modelId>/reports/<taskId>.md`。一段普通人容易理解的摘要 + 交付路径 + 真实验证情况 + 风险/待决事项即可，不需要在看板复制粘贴。
- 正式研究报告/证据优先按任务书的路径放入 `docs/planning/reports/`、`docs/planning/evidence/` 或相应研究目录。建议文件名以内部任务 ID 开头，例如 `RP-02-interface-graph.md`、`RP-02-validation.json`，便于看板自动识别。
- 复杂零件源码、参数、STEP/GLB 等按 CAD 任务书约定存放；必须在回报中列出真实路径、验证命令及是否可复现。不要假装仅凭 GLB 就具备精确工程装配关系。
- 任何需要跨模型改同一文件、变更 Schema 或推倒架构的事项写在自己的回报/阻塞中，待总控统一裁决，避免共享目录冲突。

## 4. 自主子代理（有工具时）与顺序执行（无工具时）

主 AI 负责判断任务是否值得再拆：
- 若工作环境公开提供子代理、任务或会话管理工具，可以在授权范围内**自行创建/调度/汇总**。每个子代理必须继承同一任务边界、文件契约、数据安全约束和验收规则，并用独立输出目录避免写入冲突。
- 没有真实子代理工具时，主 AI 仍然应自行研究、执行子任务并维护任务看板；**不应该要求用户为每个子任务重新启动一个模型会话**。
- 如果必须跨工具调用一个无法访问的外部模型、需要新的凭据/授权或遇到超出现有能力的工作，写 `blocked` + 明确缺少的支持。不能声称“已经唤醒 DeepSeek/Grok”等实际不存在的操作。
- 主 AI 可能在消息额度或会话结束时停止执行。它必须先把最新状态与可恢复上下文写入自己的任务卡和报告，下一次同一主 AI 进入项目即可继续。

## 5. 看板怎样展示（不维护第二份状态）

- **任务总池**：汇总所有模型的任务卡。
- **模型专属板**：显示该模型的父子任务、真实步骤、当前正在做什么、最近一次一句话报告。
- **成果回报箱**：读取个人 `reports/<taskId>.md` 与约定研究目录下以任务 ID 开头的成果文件。
- **审核**：总控在用户请求时从本地文件检查，不需要复制别的 AI 聊天原文。看板的“复制审核指令”只是可选备用按钮。
- **当前限制**：它不是跨模型 API 消息总线；不是自动进程监控器；未实测在线状态不能显示“正在实时运行”。

## 6. 最小的任务交付示例

```text
agent-workspace/agents/qwen4/
  PROFILE.md
  tasks/
    RP-01.md            # 父任务：in_progress → submitted
    RP-01-S01.md        # 子任务：parentId: RP-01
    RP-01-S02.md        # 子任务：parentId: RP-01
  reports/
    RP-01.md            # 主 AI 汇总交付、证据、风险

docs/planning/
  reports/RP-01-vehicle-product-tree.md
  evidence/RP-01-tree.json
```

用户只需启动 Qwen4 的主任务，后续子任务由它及其实际可用的内部执行能力处理；完成后对 GPT-6 说“审核 02.02（RP-01）”，我就能直接查这些路径。

## 7. 项目所有者的最小操作

1. 选择一个当前状态 `ready` 的**主任务**，在有文件权限的 Coding Agent 中启动对应模型。
2. 不为主任务自行拆出的 S01/S02/S03 逐一手动复制提示词。
3. 随时打开 `http://localhost:5174/#dispatch` 看状态和实际成果。
4. 希望检查时直接对 GPT-6 说：“检查 CARLAB 所有已提交任务，审核交付文件并更新看板。” 
5. 只有纯网页聊天模型没有项目文件权限时，才需要通过复制/粘贴回报做人工中转。
