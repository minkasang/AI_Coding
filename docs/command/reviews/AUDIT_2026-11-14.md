## 3. 跨模型整合必须处理的 P0 冲突

1. **坐标与局部装配 Frame**：现有浏览器 `+Y` 朝上、`+Z` 朝车头、`+X` 朝左；RP-02 示例 `x` 前/`y` 左/`z` 上，且自标 `OPEN`。CAD 轮端以自身局部 Z 轴为轴向。须先冻结**统一世界坐标 + 每种局部 Frame 到世界 Frame 的刚体变换**，附正反转换用例。不能直接拿示例 JSON 的坐标解释当前车辆。
2. **同名“真实性”其实是三种不同字段**：`fidelity`（视觉/几何/运动学/动力学能力）、`evidence`（公开来源/假设/未知）、`verification`（未测/已测/待审/通过/失败）必须分别编码。RP-01/02/03/06 自有词汇不能未经审核直接合并。
3. **零件身份与实例身份**：唯一 `partId`、可复用 `familyId`、重复安装的 `instanceId`、连接 `MountFrame/Joint` 及配件所属系统统一约定。产品树 ref 指针不是实际铰链。
4. **首发平台配置**：Qwen4 提出承载结构 `BOF/UNI` × 动力形式 `ICE/BEV/HEV` 两轴是合适的研究方向；首发越野/通用底盘基型、AWD/4WD 范围仍未获最终决策。
5. **平台化与物理门禁**：P0 先安全版本基线，再冻结最小接口，再做轮端+悬架完整纵切样板；不要一次生成 493 件不具尺寸依据的几何，不能把网页上看到的拉伸动画当刚体运动。
