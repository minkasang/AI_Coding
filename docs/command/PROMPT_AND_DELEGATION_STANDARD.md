# CARLAB｜高质量派工提示词与 AI 自主规划协议

> 版本：2026-11-14 · 执行中。此文件是 `AGENTS.md` 第 0 节的具体操作规范。**总控定义任务，执行者决定子任务与执行步骤**。

## 1. 总控只冻结目标和验收，不固定路径

一张优秀的父任务提示词必须回答：

1. **愿景与任务价值**：为什么研究/开发这部分；对“真实、可拆装、可复用、Chrome 高品质整车”有什么帮助？表达清楚问题和成功状态。
2. **已知背景**：已有代码与文档、已验证结果、待确定问题；不要让模型重复搭建已通过的法兰链路。
3. **目标与交付**：必须形成哪些可被下游 Agent 接手的成果（例如结构树、接口契约、脚本、图谱、CAD 源、测试）。给出目标文件夹，允许 Agent 合理拆成更多文件。
4. **真实性与质量**：可靠资料/实测与假设分级；机械拓扑、单位/坐标、可复用性、测试/错误用例、浏览器性能等，按任务挑最关键的要求。
5. **不可越界**：允许写入目录、不能破坏的基线、未经审批不可调整的跨模型接口、F 盘环境/缓存预算；必须升级总控审批的决策。
6. **可自主决定的空间**：研究路线、参考技术、工具选择、子任务数量、步骤顺序、实验设计允许 Agent 自己定；有更好方法可以重组自己的计划，说明依据。
7. **验证与汇报**：完成定义、客观证据、来源/命令/输出、无法证明之处；项目所有者能看懂的简短总结。

**禁止两种极端**：一是“随便做辆复杂车”而没有边界、交付和质量标准；二是总控随手写 20 个步骤，要求执行 AI 逐条照做并误导进度。

## 2. 派工模板（可复制）

```text
角色：你是 CARLAB 项目负责【领域】的执行/研究 AI，任务编号：【父任务 ID】。
项目愿景：【描述最终想得到的工程效果和用户价值，不写死实现步骤】。
任务目标：【本轮必须回答的问题或创造的能力；与其他任务边界明确】。
已知输入：【项目路径/已验证成果/必读文档/已有能力和不足】。
交付结果：【可继续开发使用的源文件、结构化资料、可视化说明、验证材料；目标存放位置】。
质量验收：【应如何证明准确、可复用、能运行；至少哪些关键反例要考虑】。
硬性约束：【文件允许修改范围、兼容要求、数据真实性、F 盘与依赖限制、不得伪造事实】。
自主权限：请你自主研究实现路线，按实际情况规划和创建子任务及具体步骤；可以优化/调整自己的路线，
         不用逐条照搬总控的探索建议。跨模型接口或范围有冲突时先提出方案，等待总控审核。
工作流程：读取 AGENTS.md + 本任务；确认前置条件；更新父任务状态；
         创建/更新属于自己的子任务卡；在研究/执行中持续反馈可验证进度；提交文件与证据。
结束时：用普通人理解的一句话说明做了什么、为什么有价值，列出文件、验证、风险与接下来的工作；
       标 submitted 等待审核，不自行 approved。
```

## 3. 自主拆解任务卡的格式

父任务卡在 **领取前** 可以只有任务目标和 `## 执行步骤` 下的“待自行规划”提示，没有复选框；看板要显示 **待规划** 而非完成率 0%。模型领取时改为 `in_progress`。

需要多个子任务时，在自己的目录：
`agent-workspace/agents/<modelId>/tasks/<父任务ID>-S01.md`，随后 S02、S03……（具体数量由 AI 自主选择）。父任务旧 ID 不改。

**示例：**

```md
---
id: RP-01-S01
parentId: RP-01
displayCode: 02.02.01
workstream: 整车蓝图研究
owner: qwen4
title: 梳理底盘与车架的产品结构
status: ready
priority: P0
stage: 规划深化 · 整车结构
summary: 研究底盘与车架包括哪些总成和零件。
method: 按实际工程分类查证，并对照当前项目已有结构。
learning: 装配树描述产品的层级关系。
brief: docs/tasks/RP-01-vehicle-system-breakdown.md
lastNote: 已建立子任务；尚未开始执行。
---
# 自主子任务：底盘与车架

## 执行步骤
- [ ] 根据现有资料确定分类和边界
- [ ] 产生可核对的结构与差异表
- [ ] 保存验证结果并更新父任务的整体摘要
```

**注意**：这仅是格式举例，**不是要求 Qwen4 必须创建这个具体子任务**。所有新子任务 `id` 必须唯一，`parentId` 要准确引用已有父任务的内部 ID，`displayCode` 用父任务序号扩展；`owner` 必须属于当前模型。父任务和子任务的状态都来自各自 MD，不另设一份数据库。自定义子任务可继续嵌套一层，但不要无限细分。

## 4. 看板上的进度应怎样理解

- **父任务无执行步骤/无子任务**：显示“待自主规划”，不能当作 0% 工程进度；`ready` 仅表示可以领取。
- **有子任务**：模型专属板列出父/子关系；父任务显示来自已拆解步骤的进度摘要，子任务自身独立记录步骤和回报。
- **规划完成≠成果完成**：填写子任务卡不算研究或代码交付，不能因“新建了六项步骤”就提升百分比。
- **没有文件权限的网页 AI**：只能在聊天返回拟定的子任务/研究结果，由用户或能访问文件的 AI 代录；不得声称已修改本地 MD。
- **变更/撤回**：AI 可以合理重排本模型子任务，但取消有历史成果的任务应保留记录，不删掉证据；如果改变共享架构或其他模型任务，需总控决定。
- **审核**：模型可以更新 `ready/in_progress/submitted/blocked`，总控/独立验证才可以给 `approved`。

## 5. 提示词质量检查（总控发出前必做）

- 一个没参与对话的 AI 能否仅凭提示词、文件路径和可读取材料理解真实目标？
- 是否明确区分 **必须满足** 与 **可以自主探索**？
- 是否把**工程事实、假设、未知、未验证**分开？
- 是否有明确的交付和验证，不是“写一份全面报告”？
- 是否避免过度规定操作步骤，却足够防止做偏、重复和破坏原代码？
- 任务的输入/输出能否被下游 AI 和独立审查消费？
- 用户看到的一句话摘要是否真实、明白、不堆术语？

任务达不到以上标准，**应先改进提示词再派给模型**，不能把提示词质量问题转嫁给执行者。
