# CARLAB｜任务编号与命名规则（人能看懂版）

> 版本：2026-11-14。此规则针对当前 17 张任务卡。所有正式任务状态仍在 `agent-workspace/agents/<模型>/tasks/*.md` 中；本文件不是另一份进度表。

## 为什么以前的任务编号乱

早期增加任务时分别使用了 `C-001`（总控）、`A-00`（审计）、`ENV-01`（环境）、`R-01`（研究）、`RP-01`（规划深化）、`UX-01`（体验）。它们代表不同任务类型，不是全项目的统一执行序号，因此会出现 `R-01` 和 `RP-01` 并存、A-00 与 C-001 跳号等情况。

**现已保留旧 ID 作为系统内部文件键，给人展示统一序号、中文阶段与中文任务名。** 不直接改文件名和内部键，是为了保护已有回报、任务书、Git/代码链接和旧模型会话中的引用。

## 统一的可读序号

| 序号组 | 中文工作组 | 包含内容 | 当前例子 |
|---|---|---|---|
| `01.xx` | 项目准备与统筹 | 总指挥、原程序保护、基础工具验证 | `01.02` 检查并保护现有汽车项目 |
| `02.xx` | 整车蓝图研究 | 系统零件树、接口关系、物理真实度、建模方法、浏览器体验、查漏与蓝图汇总 | `02.02` 画出整车的系统、总成与零件树 |
| `03.xx` | 后续专项研究 | 平台家族、装配协议、多零件 CAD、悬架物理、渲染、看板体验 | `03.05` 研究高质量汽车机械渲染 |

例：`02.03 · 研究车上各系统如何连接`。第一段 **02 是工作组**，第二段 **03 是组内固定序号**。

**注意：序号不是排队执行顺序。** `02.02` 与 `02.03` 可以同时研究；`02.07` 由于依赖研究结果，即使有序号也不能提前开始。是否能开始看状态 `ready/in_progress/backlog`、前置条件和任务书，而不是只看数字大小。

## 内部字段（在任务 Markdown 的 YAML 区块）

```yaml
id: RP-02
displayCode: 02.03
workstream: 整车蓝图研究
owner: deepseek
title: 研究车上各系统如何连接和影响彼此
status: ready
```

- `id`：稳定的**内部文件标识**。用于文件名、回报归档、API、已有外部链接，不应随意改。
- `displayCode`：统一的**人类可读序号**。在网页首页、总任务池、派发卡和详情中展示。
- `workstream`：中文任务工作组。网页从任务卡读取，无需另建重复状态清单。
- `title`：优先使用动词开头、普通人能看懂的一句话，例如“研究车上的制动、转向和电气怎样相互连接”，不要只有抽象缩写。
- `status`：真实进度；只按实际执行结果更新，不能用编号自动推测。

## 未来怎么编号

1. 由总控从对应工作组中分配**未使用过的序号**；同组 `01.04`、`02.09`、`03.07` 依次递增。
2. 新的正式大工作包可以新增 `04.xx` 等，先给出中文分组名称和边界，不提前写死未来所有层级。
3. 任务转交另一个模型时 **不换可读编号或内部 ID**，只改变 `owner` 和任务文件所在目录；其余引用应保持一致。
4. 任务被暂缓或归档时 **不回收序号**，以免历史报告指向另一项任务。
5. AI 执行任务时同时识别 `displayCode` 与 `id`；用户平常只用看 `displayCode + title`。
6. 不根据完成百分比或优先级修改序号；进度和序号是两个概念。

## 显示方式

建议看板以 `02.02｜画出整车的系统、总成与零件树` 作为主要内容，`Qwen4 · 待领取` 为辅助信息。
仅在“执行信息 / 原始文件”中显示内部编号 `RP-01`；复制给 AI 的完整任务提示词包含两者，避免运行时找不到文件。

## 自主子任务的编号

执行模型自行创建的子任务，在父任务可读编号后追加两位序号，如父任务 `02.02` 的子任务 `02.02.01`、`02.02.02`。内部 ID 可以是 `RP-01-S01` / `RP-01-S02`，必须声明 `parentId: RP-01`。可继续嵌套，但只在工作确实需要时分解，不为了凑卡片而人为增加层级。

旧父任务 ID 保持不变；是否可以开工依据状态与依赖，不依据序号。具体执行任务数量、顺序和步骤由领取任务的模型自行决定。
