# CARLAB｜总指挥工作台（Command Center）

> 责任划分：ChatGPT 在**每次被用户调用时**提供研究审查、架构规划、任务指派和验收；其他 AI（Gemini / Flash / DeepSeek / Codex）由用户单独启动，按任务书交付。此文件不意味着 AI 已在后台运行，也不授予自动执行高风险操作的权限。
> 总体计划：`../../MASTER_PLAN.md` ｜ 已有证据：`../research/RESEARCH_BASELINE.md` ｜任务目录：`../tasks/` ｜决策记录：`../decisions/DECISIONS.md`

## 1. 职能与决策权限

| 角色 | 工作范围 | 明确不能做的事 |
|---|---|---|
| 总指挥 / Chief Architect（ChatGPT） | 维护愿景、架构、优先级、关键研究、跨模块接口、任务拆分与验收；识别错误研究结论；把研究决定落实到计划 | 未实际调用工具时，不声称后台监控或已经派发任务 |
| 技术研究 Agent（Flash/DeepSeek 或其它） | 在给定问题和证据要求下调查、形成设计候选、最小案例、引用与可测试规则；提出未知事项 | 不直接修改生产代码，不单方面将假设定为标准 |
| 实现 Agent（Flash/Gemini/Codex 等） | 严格按照指定 schema、接口、目录和验收脚本编写代码/参数化零件，运行测试，保留证据 | 不自行替换架构、依赖、物理引擎，不跨任务大改模块 |
| 独立验证 Agent | 重跑可执行验证；对比 CAD/GLB 尺寸、装配关系、网页运行截图和旧版回归 | 不因为开发者说 PASS 就直接放行 |
| 集成 Agent（能力较强的 AI） | 合并各分支成果、检查 API/Schema 兼容性、解决冲突、维护可运行状态 | 不未经审核就修改共享数据规范 |
| 用户 / 项目所有者 | 选择方向、确定实际车型目标、批准会改变范围/许可证/安全性/成本的决定 | 无需亲自追踪每个实现细节 |

**不得把 ChatGPT 的跨会话自主调度视为已经部署**。没有自动化任务或真实连接调用，所有任务均为“待用户启动”。每次用户带回其他模型成果，先复查再改变状态。

## 2. 研究 → 决策 → 实现 → 验收（强制门禁）

```text
用户愿景与需求
  ↓
研究单 R-XX：查证 + 方案候选 + 反例 + 可执行验收用例
  ↓
总控审查：APPROVED / NEEDS_WORK / REJECTED
  ↓
ADR：DECISIONS.md 明确取舍、版本、对下游影响
  ↓
实现单 I-XX：输入/输出/接口/目标文件/不允许修改/测试命令
  ↓
实现 Agent：独立提交代码、源码资产、测试、截图
  ↓
独立审查：检查文件与运行结果；失败退回
  ↓
集成：合并、基线回归、更新记录
```

**硬门禁**：
- R-01（平台家族/固定可变硬点）与 R-02（零件/装配数据契约）经审查前，不启动批量 CAD/整车建模。
- Git 基线和已有四种页面模式快照建立前，不启动影响 `src/` 的重构。
- 项目现有 hello_flange 的 STEP→STL→GLB 已完成，但没有证明浏览器通用装配系统已实现。
- Flash 只负责一个问题/一个模块/一套明确接口。复杂子系统要再拆小，边界清晰后再实施。
- 基本结构和工程真实性先于后期视觉；不要在 P0 大规模迁移 WebGPU。

## 3. 任务状态和等级

任务卡 `status` 统一使用小写：`backlog`（未排期）、`ready`（待领取）、`in_progress`（进行中）、`submitted`（待审）、`approved`（已验收）、`needs_work`（返工）、`blocked`（阻塞）。**所有进度仅从每模型的 Markdown 任务卡计算。**

- **只凭用户/日志说“完成”只能标 SUBMITTED**；有源文件、可验证命令和独立复查后才标 APPROVED。
- 严格区分 `RESEARCH`、`IMPLEMENTATION`、`AUDIT`、`INTEGRATION` 类型，避免研究代理越界改代码。
- 每个任务有 `taskId`、`owner`、`baseRevision`、`dependencies`、`allowedPaths`、`forbiddenPaths`、`deliverables`、`acceptance`、`evidence`、`risk`。
- 发现协议冲突/工程资料不足，允许写 `BLOCKED + 缺少什么证据`，而不是编造技术答案。

## 5. 如何向较弱的 AI 派任务

每次只发送一张任务单。可以加以下统一开头：

> 你只负责任务 ID 所描述的工作。先阅读项目 `AGENTS.md`、`MASTER_PLAN.md`、`docs/research/RESEARCH_BASELINE.md` 和这张任务单。不要重写总架构，不要扩大范围。先检查任务输入和前置条件；只能修改 allowedPaths；提供确切文件路径、运行命令、验证输出；未知或无法核实就说明，不要猜测已完成。任何接口变动必须提出建议，而非直接修改共享规范。

**分配原则**：
- Flash：资料检索清单、参数/字段整理、明确接口的单模块实现、单测。
- DeepSeek：对照研究、算法原型、约束检查、针对性 review。
- Gemini（本机）：CAD/Blender 实际运行、生成零件、维护环境、GLB 流程。
- Codex 或强推理模型：跨层架构整合、测试与复杂问题排查。
以上是任务建议，不是对模型能力的保证；实际按结果调整。

## 7. 回报与交付格式（一个任务一份报告）

在 `docs/tasks/reports/<taskId>-report.md`（或对应任务指定路径）写：
1. **完成了什么**：不超过五句话；`APPROVED` 只能由审查方设置。
2. **证据**：文件的绝对路径、外部引用与访问日期、运行命令、原始测试输出、截图/尺寸表。
3. **范围差异**：更改哪些文件、为什么，未完成什么。
4. **阻塞/疑问**：信息缺口，是否影响后续任务。
5. **下一步建议**：具体可执行任务，而不是新愿景。

**总控每轮汇报**（简短）：`进行中 / 新增文件 / 可运行验证 / 风险与阻塞 / 下一批任务`。

## 10. 实际协作闭环：文件直交、内部子任务（2026-11-14）

当前默认使用 `docs/command/FILE_HANDOFF_PROTOCOL.md` 的**文件协作闭环**。用户只负责首次启动主模型任务；主模型在自身权限内自主拆分子任务、调度真实可用的子代理或在同一会话执行；进展和文件直接写入项目。看板扫描任务卡、个人回报和约定的研究证据目录，不需要用户二次粘贴。

总控 GPT-6 不在无人调用时后台调度；用户随时提醒“检查 CARLAB 已提交任务”，总控利用本机文件连接读取真实成果并审查。只读到 `submitted` 状态而缺少文件，不能认为已完成；有产物但尚未 `submitted` 的仍属于执行中，不能提前批准。需要跨工具身份、付费调用或权限才能启动的模型，必须如实声明阻塞，不能把“计划创建子代理”写成“已执行”。

旧第 5/7/8 节中人工中转及静态 R-XX 任务分配说明仅作为历史或没有文件权限时的备用；当前工作优先级以 `agent-workspace/agents/*/tasks/*.md` 实际状态为准，不能覆盖模型已经自主创建的子任务。
