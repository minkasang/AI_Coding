# CARLAB｜总计划成熟度审查（P0 执行基线）

> 审查日期：2026-11-14。依据：`MASTER_PLAN.md`、`docs/command/COMMAND_CENTER.md`、`docs/research/RESEARCH_BASELINE.md`、`docs/vehicle-platform-architecture-research.md`、以及 build123d/Blender 本机验证报告。
> 目标是说明哪些部分可按计划执行，哪些必须留待研究/实验后再冻结；并非宣称已经完成工程设计。

## 结论

**可以开始 P0 的并行研究任务；暂时不具备批量生成真实零件或大规模重构整车的条件。**
现有总计划已明确长期目标、技术栈、数据流、模块化原则和 P0–P5 的阶段路线，因此没有必要重新写一套愿景。
当前最关键的是把 **研究结论转化成可测试的接口契约**，否则各 AI 即使产出大量模型，也难以复用或装配。

## 当前已确定且有可查成果的部分

| 领域 | 已确定的工作原则/实证 | 后续限制 |
|---|---|---|
| 浏览器形态 | 现有 Three.js + WebGL 的本地演示，Chrome 浏览器作为主要交互端 | 不以 WebGPU 升级替代高质量零件与材质 |
| CAD 自动生成 | Python 3.13 + build123d 0.13.0；法兰 STEP/STL、Blender 5.2.2 GLB 测试通过 | 只验证单零件，不能证明完整装配链 |
| 存储 | 工具链在 F 盘，C 盘大量占用需避免 | 不应引入无测试收益的大体积依赖 |
| 平台化方向 | 需要 PlatformFamily、可变尺寸、固定硬点、模块接口及变型传播规则 | 厂商共性原则 ≠ 已经有本项目的可运行规则 |
| 工程真实性 | 几何/装配、运动学、动力学、视觉表现分级验收 | 原有 Cannon RaycastVehicle 不代表工程级车辆动力学 |
| 多 AI 协作 | GPT-6 统筹；研究→架构决策→实现→独立验收；独立任务卡与回报文件 | 尚未建立自动模型连接/无人值守调度 |

## 研究关口与审批依赖（真实可派发任务）

- **A-00（项目安全基线）**：检查原车 4 个演示模式、保存截图/日志、版本控制方案，避免多人覆盖旧代码。
- **R-01（Qwen4）**：平台家族、固定/可变硬点、轴距/轮距依赖传播，至少一组非法配置。
- **R-02（DeepSeek）**：零件定义/实例/装配/Joint 的数据契约，单位与坐标、公差和校验案例。
- **R-03（Gemini）**：两个以上独立零件的 CAD→网格→GLB 及实例/层级/装配信息保留实验。
- **R-04（Grok）**：双叉臂悬架运动学、硬点、自由度、约束与 Raycast/专业动力学边界。
- **R-05（HY4）**：轮毂几何质量、PBR 材质、环境反射、光照/性能分层和对比验证标准。
- **UX-01（Composer）**：本地 AI 指挥看板的布局、交互和任务认领流程审查，不先改平台基础规范。

## 暂不能冻结的 5 项设计

1. `PlatformFamily / VehicleVariant` 的字段、合法配置集合、固定硬点与变化传播。
2. `PartSpec / Assembly / Joint / MountFrame` 的共享 Schema、坐标系和实例身份。
3. build123d/Blender/glTF 的零件装配层级、材料和变换数据的可靠传递方式。
4. 悬架从动画到运动学到车辆动力学的验证等级、可复现测试数据。
5. 浏览器渲染的可观测画质/性能基线和迁移 WebGPU 的真实收益。

补充工程治理项：Git 基线、安全备份、测试自动化、资产许可与版权、研究来源标识。它们要进入 P0 验收，不能因为模型输出漂亮就略过。

## 实施解锁条件

- **关口 G0**：A-00 明确恢复路径与可运行基线；不先动生产演示源代码。
- **关口 G1**：R-01 + R-02 经过 GPT-6 对照审查，无矛盾后批准最小 Schema 和配置校验接口；再派发 I-01。
- **关口 G2**：R-03 给出跨零件导出与信息保留的可运行实证；再开发复用资产链与 GLB 选择器。
- **关口 G3**：第一套轮端总成有尺寸、连接、运动、渲染分别验收后，才可复制生产其他零件家族。
- **关口 G4**：整车变型至少通过短/长轴的装配/配置测试，才能扩大到 SUV/轿车平台差异。

## 沟通与派工方式（当前 V1.1）

1. 打开 `http://localhost:5174/#dispatch`。
2. 在“任务派发台”选择一个模型的研究任务，点击**复制完整任务提示词**，手动粘贴给对应 AI。
3. AI 有文件权限时更新自己的 `tasks/<id>.md` 进度，并把回报写到 `reports/<id>.md`；没有文件权限时直接在聊天里给出完整可复制回报。
4. 用户将外部聊天回报粘贴到网页，保存到该任务对应的报告文件，并自动将任务标记为 `submitted`（待审核）。
5. 用户点**复制给 GPT-6 审核**，粘贴回 ChatGPT；GPT-6 复查实际文件、证据、测试后，决定批准/返工/补充研究。
6. 上述流程是人工传递，不是各模型已经接通。状态来源仍是任务卡 Markdown；回报原文与证据独立存放。

## 当前推荐并行顺序

**优先同时启动**：R-01（平台家族）、R-02（装配数据）、A-00（安全基线）。
接着可以独立启动 R-03（CAD/GLB 流程）、R-04（悬架物理）、R-05（画质），这些任务当前只允许研究或隔离验证。
最终由总控汇总 R-01/R-02 的研究成果并冻结最小接口后，才把实现工作大量交给 Flash 类模型。

**不能误解**：模型工作区已分配任务 ≠ AI 已开始执行；页面同步频率 ≠ 自动派发频率；报告提交 ≠ 已审核通过。
