# UX-01｜让 AI 指挥看板能清楚显示每个模型的下一步

> 任务所属模型：Composer 2.5。正式状态、父子任务和进度**只取自** `agent-workspace/agents/composer-2-5/tasks/UX-01.md`；本文件是高质量任务要求，不是额外一份进度表。

## 我们想得到什么

用户在 Chrome 打开 `http://localhost:5174` 时，应该一眼看到**每个 AI 下一步需要做什么、何时可以开始、现在是否等待审核或返工**，而不是只看到“已验收”“待返工”的历史清单。已验收意味着前一项完成，不意味着模型没有下一轮工作。

同时维持原先约定：**总控给主任务，模型自己拆子任务**；用户不负责为 S01/S02 等复制提示词，更不负责转发各模型工作结果。所有状态来自 Markdown，网页不维护第二套进度数据。

## 背景和现状

- 已有可用 `command-center/`，通过 `/api/dashboard` 读取 `agent-workspace/agents/*/tasks/*.md`，并读取报告/研究成果。
- 当前父任务有 `approved / in_progress / ready / needs_work / submitted / backlog` 等状态，任务号不代表执行次序。
- 本次已为 Qwen4 开启 R-01（在执行）、DeepSeek R-02（可领取）、Grok R-04（可领取）、Composer UX-01（可领取），Gemini 和 HY4 继续处理既有返工。
- 初始 Git 仓库已建立，但不自动建立远程仓库；源项目还在 F 盘，5173 原汽车演示必须不受影响。

## 验收结果（重点是体验，而非文件数量）

1. 在总览显示清楚的“**各模型下一步**”区域，每个模型仅展示一项**主任务**（不把子任务当独立派工），包括自然语言任务名、状态、谁负责、卡点和能否启动。
2. 任务优先顺序至少区分：进行中、待返工、待审核、可领取；没有活跃任务时应显示“待总控安排”，**不能把刚完成的已验收项展示成下一项任务**。
3. 点进模型后能看到已完成历史与当前正在做/待领取任务分离；不会因为父子任务数量增加导致页面乱或夸张地宣称项目完成比例。
4. 能通过真数据进行验证：一位已验收后有新任务的模型、正在返工的模型、只有历史成果但没有新任务的模型、创建多个子任务的模型。
5. 完整保留数据源单一原则，不额外维护静态任务表；不要修改各模型的任务状态来制造视觉效果。
6. 简洁、清楚、布局克制，桌面优先但手机不乱；有轻量交互与必要动效即可，禁用动画偏好应被尊重。
7. 提供运行/检查方法、截图或页面验证记录，并用一句普通人可理解的话总结体验提升和未解决问题。

## 工程约束

- 可以修改 `command-center/app.js`、`styles.css`、`index.html`，仅在确有必要时修改只读数据投影的 `command-center/server.mjs`；不能编辑 `src/`、其他模型任务卡或 `MASTER_PLAN.md`。
- 变动必须兼容旧的 `/api/dashboard`、任务状态、已有报告接收。不要在本地生成另一个独立状态数据库。
- 所有依赖/缓存/截图留在 F 盘；不安装重依赖、不开外网端口、不添加付费外部服务。
- 自己负责验证 JS 语法和 5174 API；若修改启动方式，需能和旧 5173 并存。
- 如果需要改变跨模型数据契约、添加写入功能或影响历史任务，请先提交决定建议给 GPT-6，而非自行冻结。
