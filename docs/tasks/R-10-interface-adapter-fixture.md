# R-10｜跨模型装配接口适配器：从“发现冲突”走向可运行的协作实验

> 任务工作位：DeepSeek。前序：R-07 已提交 46 字段映射、18 冲突与 15 裁决请求。**当前仍没有被冻结的全项目正式 Schema**；本工作只在隔离目录验证适配行为，输出可供总控 RP-07 决策的证据。

## 为什么做

我们已经分别有 Qwen4 的车型平台/产品树、Gemini 的 CAD→GLB 资产描述、Grok 的悬架几何约束、以及你 R-02 的 Part/Instance/Frame 数据方案。但目前它们的 ID、版本、单位、空间坐标和数量语义不同，直接拼在一起就有可能出现“四个螺栓角”的数量加倍、轮端左右装反、同一零件的 ID 断链等错误。

下一步需要通过**一个小型、独立、能运行的适配夹具**证明：哪些输入可以无损转换，哪些只能作为未解决事项保留，哪些错误必须拒绝。

## 本任务要达成什么

- 从现有 R-02/R-07 提案读取数据，不改变现有正式项目代码，建立**候选**映射：`PART-*` 主键与外部 ID、revision 与 contentFingerprint、每总成 qty 与派生整车总数、显式 Frame/单位、BOM 追溯、fidelity/evidence/verification 区分。
- 设计至少一种**两模型交接**可复核样例（如 Qwen 轮端最小 BOM 与 Gemini 资产、Grok 运动学约束），用结构化文件明确引用和尚不具备的字段，不能虚构真实参数来把链路跑通。
- 能对错误来源/双主键、重复实例、混用 mm/m、未经声明的左右镜像、装配数量放大、过时指纹等给出**可理解的拒绝原因**。重点证明错误确实被识别，不能仅在报告里罗列。
- 同时支持尚未裁决的字段：将其标记为 OPEN / PROPOSED，不得为通过测试而擅自冻结接口。特别是 `Joint` 与通用 `Constraint` 的边界要与 Grok 协商。
- 简单比较运行后的样例结构与原研究文件：参数/关系/来源信息是否丢失？明确哪些类型暂时只能人工对齐、哪些需要 Qwen4 R-06 的真实尺寸资料。

## 交付与测试

- `docs/research/R-10-interface-adapter-fixture.md`：设计与转换边界、输入输出、可复验错误案例、未决事项和如何进入下一阶段；
- `docs/research/R-10-adapter-example.json`：带显式来源等级的样例或夹具；
- 代码与测试如有必要，放 `agent-workspace/agents/deepseek/tools/r10_*` 或 `src-experiments/interface-adapter/`，仅用现有 Node/Python 环境即可；
- 本工作位回报 `agent-workspace/agents/deepseek/reports/R-10.md`，含真实运行命令与测试结果；
- 跨模型问题通过 `agent-workspace/shared/messages/` 新建消息，不要求用户转发。模型自己按必要性拆子任务，状态先 `ready` 后实际领取。

## 必须遵守的边界

- 不直接编辑旧 `src/`、`cad/experiments/asset_pipeline_v1`、`command-center/`、其他模型任务卡和总控 `MASTER_PLAN.md`。
- 不能把测试用虚构零件尺寸、假设材料、局部工件系硬点解释成真实车型。不能只用自造规则证明工程参数真实。
- 不发布或强制修改全项目生产 Schema；所有待决接口提交给 GPT-6 的 RP-07 架构审查，相关交叉问题写入公共消息。
- 不追求几百个零件；一个真实可复验、能发现静默错误的纵切样板，比生成大量漂亮但无关节约束的网格更有价值。
- **本任务由 DeepSeek 自主研究具体技术路线、子任务数量与执行顺序**。总控只明确目标、质量门槛和需禁止的行为，模型应直接处理项目文件，而不是让用户为子任务逐项复制提示词。
