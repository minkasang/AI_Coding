# VIEW-01｜从工程查看器研究到可运行的 Chrome 样板（Composer 2.5）

## 为什么做

用户想在浏览器里观察、拆解和理解一辆零件复杂、真实可复用的汽车，而不仅是围着外观旋转。RP-06 已给出工程查看器研究；这轮需要验证其中一小段是否真的能在 Chrome 做出来，避免以后大规模生产零件才发现查看、选取和管理关系很困难。

## 预期成果

**交付一个独立、可实际打开的工程查看器原型**，优先使用当前 F 盘已有的合法三零件轮端 GLB 样例（如 `cad/experiments/planning_feasibility/out/wheel_hub_assembly.glb`）；明确展示零件与整体的关系，使普通用户能够选择零件、隐藏或隔离它、查看名称和可追踪的参数来源，并能恢复整体视图。

原型可以自主决定增加哪些有价值的最小功能（例如简易爆炸、测距、显示装配树、工程/展示双模式），但应遵循“能用、可理解、可扩展”而非一次塞满所有想法。外观必须干净、有设计感、布局严谨；避免用浮夸面板掩盖零件质量。

## 必须保持的约束

- 所有实现与运行脚本仅放 `viewer/experiments/engineering-viewer/`；必要文档写 `docs/research/VIEW-01-*.md`，证据写 `docs/research/VIEW-01-*.json`。**不得修改原 `src/`、`index.html`、已有 server、生产 schema 或其他模型任务卡。**
- F 盘优先，禁止在 C 盘安装大量依赖。不因样板需求引入新渲染框架；确有技术原因先证明必要性。
- 可引用真实 GLB，也要考虑模型输出文件是被 Git 忽略的可再生成资产：写清楚没有样例时的生成路径/处理方法，不把用户要求手动复制文件当默认。
- 明确区分 **真实的建模/装配数据** 与 **演示交互**；不能仅因为能拆开 3 个 Mesh 就声称实体机械约束、精确运动副已经实现。
- 如果已审核文档中的 API 路径有误，请依据当前安装的库修正本任务自己的使用，不擅自改旧报告。

## 验收标准

- 新样板在 Windows Chrome 中可打开；能加载现有轮端样例且失败时有明确提示，不产生黑屏静默故障；
- 能准确区别整体和独立零件，进行选择与隔离/恢复；界面为普通用户提供易理解的部件名称与操作提示；
- 给出可重复的运行与检查方式（本地命令、URL、实际操作/截图或测试记录）；不能凭源码存在宣布已验证 Chrome 实际运行；
- 说明大规模车模时的潜在瓶颈和分阶段升级策略；不得谎报 FPS 或 WEBGPU 品质提升；
- 形成可向将来正式工程查看器复用的模块划分和接口需求，接口尚未冻结时只提出建议；
- 提交自己的主任务回报，并将 status 设为 submitted，等待 GPT-6 审核。

你可以自行调查 Three.js、GLTFLoader、模型层级管理及适合的用户交互方式，自主创建子任务、决定执行先后，必要时内部委派有实际权限的子代理。**总控定义的是成果、边界和质量，不是固定施工步骤**。越界的架构/依赖变更须先写清建议与风险等待审查。
