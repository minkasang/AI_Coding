# RP-05｜整车计划的独立遗漏审计与风险清单（HY4）

## 任务授权：目标约束明确，执行路径由你自主决定

> **重要**：本任务书描述最终需要解决的问题、质量标准和交付边界；以下研究问题是覆盖要求/探索线索，不是总控预先安排的固定执行顺序。阅读项目 `AGENTS.md` 第 0 节和 `docs/command/PROMPT_AND_DELEGATION_STANDARD.md`。请先核实当前状态，**自己规划合理的技术路线，并在个人工作区按需创建带 parentId 的子任务卡**，自主调整步骤。不要为完成清单而牺牲发现新问题的机会。每项结论必须可证实、可落地，涉及跨模型接口或整体范围变化需提交总控审查。


**类型**：RESEARCH / INDEPENDENT AUDIT；**第二波**，等待 RP-01、RP-02、RP-03、RP-04、RP-06 的研究报告出现后执行。
**核心目标**：专门找大家忽略了什么，不负责替别人写方案，也不美化任何模型的工作结果。
**输入**：原 `MASTER_PLAN.md`、`docs/planning/PLANNING_PROGRAM.md`、`docs/planning/VEHICLE_SYSTEM_TREE_SEED.md`、`docs/planning/GAP_REGISTER.md`、第一波研究报告、旧 R-xx 研究说明。
**允许写**：`docs/planning/reports/RP-05-independent-gap-audit.md`、`docs/planning/evidence/RP-05-*.json`、`agent-workspace/agents/hy4/tasks/RP-05.md` 和个人回报。不得修改共享缺口表或其他模型研究。

## 审查步骤
1. 审查产品树：动力/传动/转向/制动/悬架/轮端/车架/车身/座椅/电气/线束/冷却/流体/安全/通用紧固件是否遗漏或只写了名字。
2. 审查接口图：哪个系统与另一个系统存在无定义的固定点、运动副、流体管路、电气接头或信号连接。
3. 审查真实性矩阵：把动画当仿真、把几何相交当真实装配、把 WebGPU 当作模型质量、把错误尺寸当标准等风险。
4. 审查浏览器运行成本、来源/许可、C/F 盘预算、生成物保留、可复现测试和跨 AI 版本冲突。
5. 逐条复查 GAP_REGISTER 的候选缺口，给出 `CONFIRMED_GAP / ALREADY_COVERED / NOT_REQUIRED / NEEDS_DECISION`，附原计划或报告中的位置和证据。
6. 选有代表性的跨系统端到端场景（如制动、四驱动力、冷却），追踪到产品总成、接口、建模、仿真、渲染及验收，缺一个就标明。
7. 形成风险矩阵：影响、可能性/未知、前置依赖、建议负责人、最小修复任务和优先级；不是简单列 100 项设想。

## 验收
- 独立指出能支持设计决策的“已覆盖/遗漏/不必做/待确认”判断，不要求故意凑缺口数量；
- 主要可能导致后期返工的结构或接口风险有可操作纠正建议；
- 高优先级缺口能生成明确的补充研究或实现任务；
- 每条需要核对来源，不得因为报告字数多就认为规划完整。
