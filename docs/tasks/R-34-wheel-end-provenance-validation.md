# R-34｜验证 C-01 发布包的来源门禁

## 目标

将 R-08 已验证的来源纪律用于 C-01 实际发布清单，让下游能区分可查看的演示 CAD、来源未知和证据矛盾。交付可重复执行的来源检查及一份词汇映射说明。

## 输入和边界

- 使用 `cad/experiments/vehicle-cad-pipeline-v1/out/c01-c5d74da77c293aa5321f/manifest.json`，包缺失时按 C-01 文档重建。核对包级 `sourceGrade`、零件材料来源与 `snapshotBinding.mappingStatus`。把 R-08 的 `DEMO_ESTIMATE` 与 C-01 的 `DEMO_ASSUMPTION` 分别保留在它们原有语境中，报告解释消费者如何读取。
- 实验和测试仅放在 `cad/experiments/wheel-end-provenance-v1/`，个人回报放在本工作位。C-01 和 R-08 的正式发布文件、共享来源注册表和主页面作为只读输入。实例到网格的绑定由 DeepSeek R-32 负责，运动配准由 Grok R-33 负责。

## 交付和验收

1. 交付可复跑检查及机器报告，实测 C-01 真包被接受为演示资产，记录包和各零件的来源范围、空缺项。区分包的完整性验证与实际厂商证据。
2. 用内存或独立测试夹具覆盖来源标签缺失、包与零件标签矛盾、无可靠凭证的 OEM 升级及 `TEST_ONLY` 证据被用于生产声明。对每种情况给出明确失败原因。检查产出应保留可用的演示级别信息。
3. 在个人回报中附运行命令、通过和拒绝结果及适用边界。以公共交接将来源字段说明提供给 DeepSeek 和总控，完成后提交。
