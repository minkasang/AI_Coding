# R-25｜把整车结构送进统一工作台，不再只看三颗轮端零件（Composer 2.5）

> 上一轮 R-20 测距与剖切经总控实际 Chrome 双点击验证通过。新重点是**展示一辆有层级结构的汽车工程**，而不是给每个悬架、轮毂、传动独立造页面。

先开发 `workbench-v2/experiments/vehicle-structure-adapter/`：输入 R-16 详细工程骨架、R-17 候选领域主数据，能在同一对象树中导航 `整车→系统→总成→零件实例`，支持按实例 ID 选中、定位已有 CAD、显示无几何与数据来源状态；未有 3D 模型的轮端/制动/车身只能显示明确的占位/“未建立几何”，**不允许用复制现有轮毂 GLB 来冒充整个车辆**。

用户场景必须清楚：在整车里点“底盘/左前悬架/某下摆臂”，属性检查显示该对象真实/未知状态；“展示与检查”下的高亮、聚焦、测距/剖切只在存在真实几何时启用；试验仿真另读同一个运行结果，不与对象树另建实体 ID。要与 R-22/23 共享 `instanceId`，反例覆盖不同代际同名件冲突、空几何误选、状态切换丢选择、虚假 CAD 显示、数据版本失效。

本轮先在隔离目录实现读取/渲染 adapter + Chrome 可运行交互样例；**不得覆盖正在使用中的 workbench-v2 顶层页面**，将最小接入差异形成可复查 patch 供总控整合。除非总控明确授权，不在无来源情况下把旧程序化四轮小车贴上新装配身份。交付 `docs/research/R-25-vehicle-tree-workbench.md`、可运行代码和测试、`agent-workspace/agents/composer-2-5/reports/R-25.md`。不增 5175/5181 等常驻端口。
