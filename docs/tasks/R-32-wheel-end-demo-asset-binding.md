# R-32｜左前轮端静态资产绑定

## 目标

让现有工作台能从选中的 R-27 `partInstanceId` 找到正确的 C-01 演示网格。先交付独立、可验证的静态绑定，供 Composer 在 R-29 左栏返工通过后使用。

## 输入和边界

- 复用 R-27 发布快照与 R-31 只读消费约定。C-01 验收对象为 `cad/experiments/vehicle-cad-pipeline-v1/out/c01-c5d74da77c293aa5321f/`，可按 C-01 文档重建。读取清单中的快照标识、修订、变型、SHA-256、实例身份和 GLB 层级信息。
- 实现和测试放在 `src-experiments/wheel-end-asset-binding-v1/`，回报放在本工作位。原快照、原 C-01 包与主工作台作为只读输入。与 Composer 按公共消息对齐消费方式。
- 仅关联 C-01 清单中已验证的九个左前轮端实例，使用 `DEMO_SUBSTITUTE`。保留装配层级、局部变换和快照的来源状态。整车坐标与位姿由 R-33 单独验证。

## 交付与验收

1. 提供只读消费模块、接入说明与可独立执行的测试。用真包验证九个唯一 `PI-*` 的零件定义与 GLB 节点都对应，包含五个同定义的螺柱实例。未覆盖的快照实例保留原几何状态。
2. 验证实际快照与 GLB 的校验值。修订、变型、哈希、实例身份不匹配，GLB 节点缺失或重复，或包缺失时，返回清晰原因并保留原查看状态。至少用现有三个 DEMO 零件与无几何节点检查回退边界。
3. 在同源 5173 资源上复验读取，向 Composer 交付最小的接入调用，说明如何从场景节点保留层级变换，以及在不存在整车配准时如何保持静态演示。报告附运行命令、证据和未决项，父卡标 `submitted`。
