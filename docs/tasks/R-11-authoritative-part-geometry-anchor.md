# R-11｜给首个轮端样板找一个可核验的真实几何锚（Qwen4）

**背景**：R-06 已验收：60 项 BOM、12 个阻塞界面、20 个关键参数中 17 个 UNKNOWN。现在的下一步不是再扩大到 493 件，而是先让一个子系统真正拥有可信的尺寸来源。

**任务目标**：围绕第一版左前轮端—双叉臂样板，优先选择**能够依法获取公开尺寸图的明确型号**（例如轮毂轴承+匹配法兰或球铰/转向节），建立真实来源、接口和允许建模等级的证据链。不能凑不同车辆零件假装属于同一总成。若找不到足以证明装配配合的公开资料，结论应是“暂时无法升级到配合级”，并给出可执行的下一份来源搜集方向。

## 要回答的问题
- 哪个具体制造商/产品型号、哪个图号、发行版本或产品页、哪个位置支持每个参数？是型号本身的尺寸还是通用标准？
- PCD、CB、轴承内外径/宽度、过盈/公差、螺柱安装和球铰硬点中，哪些可升级 SOURCED、哪些只能保留 UNKNOWN？不得直接拿 `src/specs.js` 兜底值当实车数据。
- 如果只能取得外形包络，是否可以先作为 `FID-V` 视觉样例交 Gemini，而对真实配合和运动学保持阻塞？
- 能否避免 Gen1/Gen3 轴承混配、商用车/乘用车混件、CAD 资产授权不明等问题？

**预期成果**：`docs/research/R-11-geometry-anchor-study.md`（来源核查、测量基准、条件适用、缺口与决定），`docs/research/R-11-geometry-evidence.example.json`（结构化字段与链接），个人 `agent-workspace/agents/qwen4/reports/R-11.md`（成果文件与结论）。研究可自主扩展一个小型检验脚本，但不能暗中修改 R-06 已验收 BOM，也不能复制无授权 OEM 资料。

**协同与验收**：向 Gemini/Grok/DeepSeek 提供的证据须按 sourceId 和适用车型/总成条件标记，公共消息写入 `agent-workspace/shared/messages/`。由 Qwen4 自主研究、建立子任务、处理可靠来源；不要求用户逐条传话。提交 `submitted` 等 GPT-6 核验；**通过标准是可追溯与诚实处理未知，不是找到多少个数。**
