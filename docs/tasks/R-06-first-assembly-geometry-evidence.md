# R-06｜为首个轮端—悬架样板建立可信的零件与几何依据

> 模型：Qwen4。目标归档：`agent-workspace/agents/qwen4/tasks/R-06.md`；已通过的前序研究：`RP-01` 整车零件树、`R-01` 多车型变型规则。任务目标与验收要求由总控确定；**技术路径、子任务数量、研究顺序由 Qwen4 自主设计**。

## 为什么现在要做

CARLAB 希望在 Chrome 中展示一辆机械结构足够真实、悬架和传动能正确运动、未来可以配置成不同车型的小车。前两轮已经建立了零件分类和变型规则，但 RP-01 的 493 个零件尚无逐件可核对的真实几何尺寸。若现在批量让 AI 生成“很像汽车”的 CAD，螺丝、球铰、减振器、转向节、轮毂的比例及连接可能仍属猜测。

**这一轮成功的样子**：后续建模 AI 能拿着你给出的**一份范围清晰、可以追溯来源、有装配界面约束的零件需求单**，知道哪些尺寸有可靠公开证据、哪些必须保留 UNKNOWN、哪些几何可以暂时用明确的演示假设替代、哪些关键连接不能猜。

## 工作范围与跨模型分工

聚焦**第一个可验证的轮端—双叉臂悬架局部样板**，不要一口气列完 493 件，更不要把任意量产车的不同零件混成“真实同一车辆总成”。范围可包含但不限于：车轮/轮胎、轮毂、制动盘/卡钳、轮毂轴承、转向节、球铰、上下摆臂、弹簧减振器、转向拉杆、必要的轴头与紧固连接。由你根据机械依赖决定哪些必须进入最小样板，哪些先延期。

- 与 **Grok R-04** 区分：Qwen4 研究**零件定义、制造/几何资料、连接界面**；Grok 研究**运动链、自由度、行程与几何运动学**。
- 与 **Gemini R-03** 区分：Qwen4 交付可靠的**尺寸证据和零件需求**；Gemini 负责**参数化 CAD/装配与导出流水线**。
- 与 **DeepSeek R-02** 区分：Qwen4 提供 BOM 字段和装配身份需求建议；不自行冻结全局 `PartSpec`、`Frame` 或 `Joint` 正式协议。
- 与总控 **RP-07** 区分：这里提供有证据的技术输入；不直接宣布车系设计规范已通过。

## 你应解决的核心问题

1. 首个局部样板要包含哪些真实物理部件、紧固件与安装关系？区分“真实机构必需”与“只为视觉效果的可选细节”；形成层级 BOM 及总成边界。
2. 每类关键参数究竟需要哪种证据？例如轮毂 PCD、中心孔、轴承内外径/宽度、轮胎规格、球铰锥度、摆臂安装中心距、螺栓规格与等级、制动盘帽高、减振器行程、干涉包络等。**不是要求都查到**，而是明确最小验证需求和空缺。
3. 尽量优先权威标准、零件制造商产品目录/官方尺寸图、公开工程资料、合法授权 CAD；每条来源都保留 URL/页码或图号/版本/获取日期/可信度。查不到应写 `UNKNOWN`，绝不编造值。
4. 用能被下游 AI 使用的结构化形式记录参数、单位、公差（如有证据）、来源等级、坐标参考点/局部安装 Frame 建议、适用边界。禁止用“换壳”和全局 mesh 缩放伪装真实机械装配。
5. 遇到目录零件的几何图纸与实际装配拓扑不匹配、接口尺寸冲突、许可证不明、不同车型零件混配时，应如何发出可理解的错误而非默默接受？
6. 给出**一小套代表性的可验证示例**，用于之后由 Gemini/Grok 做 CAD 和运动学验证；可以使用演示假设，但要清楚标识，不允许拿示例当 OEM 参数。
