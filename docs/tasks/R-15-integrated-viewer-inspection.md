# R-15｜统一小车工坊的机械装配检查体验（Composer 2.5）

**背景**：VIEW-01 的单位问题返工已验收，GPT-6 已将查看器整合到 `http://localhost:5173` 的第五个「零件装配」页面。新 UI 采用浅色工业设计，旧四个模拟视图保留。现有功能可查看、选中、隔离、X 光、爆炸三类轮端演示零件，但还没有真正的尺寸测量/剖切/空间定位体验。

**目标**：进一步提高「零件装配」的日常可用性和工程学习价值。给用户少量高价值、直观、可靠的操作（例如二点测距、局部剖切/轴向切面、尺寸包围盒/装配关系说明），让用户不仅看到“一个金属块”，还知道这个零件与其它零件如何相关。

**质量标准**：
- 保留顶部工坊五视图、浅色风格、右侧检查器，不能重新造一个暗色独立成品；原整车模式与 Cannon-es 仿真不得破坏。
- 机械测距一定明确单位（米与毫米），剖切/爆炸是**视觉操作**不代表拆卸工艺/真实关节运动；资料缺失必须显示 UNKNOWN。
- 优先使用现有 GLB 元数据，不可发明真实螺纹、OEM 材质/强度或校验等级；如需要对接 DeepSeek/Gemini/Grok 的接口须通过公共消息。
- 先在 `viewer/experiments/engineering-viewer/` 的专属范围内试验和回归，涉及共享 `index.html/src/main.js` 主页面的修改，先写提案由 GPT-6 统一合并。
- 提供实际 Chrome 可见的工程截图，验证交互是真的有效，而非仅检查 DOM 或报告中的 PASS；保留单独 Viewer 测试入口但不要把 5175 当主产品。

**交付**：`docs/research/R-15-viewer-inspection.md`，必要的单独 Viewer 功能源代码、可复跑测试与本人 `agent-workspace/agents/composer-2-5/reports/R-15.md`。具体实施路线、子任务由 Composer 自己决定，用户不需要逐项传话。
