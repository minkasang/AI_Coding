# R-16｜让整车成为可追溯的工程对象树（Qwen4）

> 工作位：qwen4，P0；前置：R-11 研究验收，RP-01/R-06 数据与证据可读。**目标是可验证的整车工程骨架，不是几百个假几何零件。**

## 目标
将已有 RP-01 系统/总成/零件研究结构转换为一个**可供后续工程编辑、展示、仿真共同引用的车辆对象骨架样例**：整车 → 车架 / 前后悬架 / 转向 / 动力传动 / 制动 / 四角轮端 → 总成 → 可辨识零件实例。树中没有具体可用 CAD 的位置用 `GEOMETRY_PENDING`，没有质量和安装参数的位置用 `UNKNOWN`。不借现有 Three.js 小车的管件替换缺失的真 CAD。

## 必须解决
1. 区分 `System`（功能分类）、`Assembly`（真实采购/装配边界）、`PartDefinition`（零件族/款式）与 `PartInstance`（具体左前、右前等装车实例）。同一零件族多个实例不能被“familyId 去重”吞掉。
2. 完整四角轮端身份及左右/前后条件：镜像不能通过单纯全局 scale 改变物理几何；明确哪些 Instance 需要不同的安装 Frame。
3. 针对 R-11 自我发现的 `螺柱+螺母 / 轮螺栓` 两种安装架构建立**可组合但互斥**的候选规则；Gen1/Gen3 轴承法兰也须条件互斥，不能把 Dorman 610-460 自行装进目标车型。
4. 最小结构应覆盖全车主要系统，**真实几何深度只选一个可动轮端纵切**；列出哪些“轮毂、摆臂、球铰、弹簧、转向节、车架硬点”因证据缺失仍处于 MODEL_BLOCKED。
5. 预留对 DeepSeek R-17 的 `instanceId` / `frameId` 映射和具体证据来源字段，**不擅自冻结生产 Schema**。源数据继承规则必须防止 ASSUMPTION/UNKNOWN 被升级。
