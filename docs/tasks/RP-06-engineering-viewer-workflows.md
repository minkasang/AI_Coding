# RP-06｜汽车工程查看与学习体验的功能规划（Composer 2.5）

## 任务授权：目标约束明确，执行路径由你自主决定

> **重要**：本任务书描述最终需要解决的问题、质量标准和交付边界；以下研究问题是覆盖要求/探索线索，不是总控预先安排的固定执行顺序。阅读项目 `AGENTS.md` 第 0 节和 `docs/command/PROMPT_AND_DELEGATION_STANDARD.md`。请先核实当前状态，**自己规划合理的技术路线，并在个人工作区按需创建带 parentId 的子任务卡**，自主调整步骤。不要为完成清单而牺牲发现新问题的机会。每项结论必须可证实、可落地，涉及跨模型接口或整体范围变化需提交总控审查。


**研究目标**：用户打开 Chrome 看到精细车辆时，怎样理解、检查和比较机械关系，而不只是围着模型转？
**类型**：RESEARCH / PRODUCT WORKFLOW；第一波并行。与旧 UX-01（AI 指挥看板体验）是不同产品。
**输入**：`MASTER_PLAN.md`、`docs/planning/PLANNING_PROGRAM.md`、`docs/planning/VEHICLE_SYSTEM_TREE_SEED.md`、`src/main.js`（只读），目前轮毂/悬架截图和项目实际可运行页面。
**允许写**：`docs/planning/reports/RP-06-engineering-viewer.md`、`docs/planning/evidence/RP-06-*.json`、`agent-workspace/agents/composer-2-5/tasks/RP-06.md` 和个人回报。不能更改现有 Web 代码、AI 指挥看板或全局架构。

## 必须完成
1. 提出覆盖关键需求的核心用户旅程：整车浏览→总成定位→零件选择→参数与材质查看→爆炸/装回→装配运动→工况比较→追溯证据。
2. 研究同一车辆的“工程模式”和“高画质展示模式”应有哪些不同控件、信息密度和性能取舍。
3. 在大规模复杂模型里如何按系统树导航、搜索零件、剖切、透明、隔离、测距、查看 BOM、显示运动副、变型前后差异；哪些功能有现成 Three.js 支持，哪些需要自研。
4. 解释如何在 UI 上明确标注“演示动画 / 运动学 / 动力学”、“有来源尺寸 / 假设尺寸”、“已验证 / 待验证”，避免画面精美误导用户。
5. 产出简洁的界面信息架构图和页面功能分层，不写 CSS/页面代码，不要塞进复杂功能变成一个杂乱的超级控制面板。
6. 提出性能和可用性验证方案：加载量、互动反馈、按需显示、不同分辨率、是否影响旧四模式、可读性与错误提示。
7. 每项建议给 MVP / LATER / REQUIRES_RESEARCH 分类；引用真实可核查的官方三维 API/交互案例，区分事实与产品设计建议。
