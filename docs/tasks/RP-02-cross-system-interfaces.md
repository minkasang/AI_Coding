## 必须产出
1. 分离六类接口：机械力/运动、电子电能、信息/控制、流体/液压、热交换、接触/环境；说明连接对象、输入输出、单位、双向/单向与失效条件。
2. 以“制动一次”“方向盘转向+悬架跳动”“发动机冷却”“电驱加速/回收制动”四个场景分别给出**因果链和参与总成**。
3. 对轴距、轮距、离地间隙、发动机→电驱、悬架拓扑变化给出依赖传播表：哪些零件/装配点/管路/算法/质量属性要重算，哪些条件会失败。
4. 区分“工程连接 Frame”和“渲染可见接触”；不要因为 Mesh 贴合就推断机械可传力。
5. 输出一个可解析的示例接口图 JSON（`nodes / edges / type / units / evidence / validation`），标明哪些信息尚不知道，不能凭空编造汽车线束详细协议。
6. 覆盖关键正常与异常情形的可自动测试案例（含断开、单位不匹配、接口不兼容、循环/冲突、传播遗漏）。
7. 采用可信公开技术说明或标准作为必要证据；所有设计 API 是项目提案而非汽车行业统一既成标准。

## 验收
- 四种关键场景有完整“输入→跨系统→响应”链；
- 可以根据示例 JSON 设计接口依赖引擎，且明确与 RP-01、原 R-02 的待对齐点；
- 给下游 AI 一份最小接口字段表与明确失败条件，而不是抽象“各模块联动”。
